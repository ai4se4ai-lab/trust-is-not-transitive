\section{Wrap-Up: The Whole Argument in One Page}
\label{ch:wrapup}
% =====================================================================

\begin{bigidea}
Guardrails promise conditionally. \emph{Evidence for a promise belongs to one invocation of one stage}; the only way it travels forward is through a \emph{deterministic gate that provides a fact}. From this single design choice the paper derives a composition check that is \emph{sound and complete}, shows the popular transitive argument \emph{unsound}, classifies the problem as \emph{near-linear without facts and coNP-complete in general}, and builds \emph{route-level statistical certificates} on top. What it gives engineers is chiefly a \emph{list of what an assurance argument rests on}.
\end{bigidea}

\subsection{Five lessons for a software engineer}

\begin{enumerate}
\item \textbf{Write down the assumption next to every guarantee.} A promise without its assumption is a hazard.
\item \textbf{Make assumptions \emph{established}, not inherited.} If a property must hold downstream, put a mechanism (a deterministic gate) that establishes it, and put that mechanism on the claims list.
\item \textbf{Prefer deterministic establishment.} Exact gates on typed actions and labels need no statistics and survive adaptive attackers (given complete mediation). Learned guards can only reduce risk, with a bound that depends on the traffic.
\item \textbf{Keep the guard away from the attacker's text if you can.} Non-interference says a guard that judges content must read content; the lead-lined suitcase is a consequence, not an accident.
\item \textbf{Count routes, not layers.} Risk adds up across the places an unsafe action can get out; multiplying per-layer rates assumes independence you cannot assume.
\end{enumerate}

\subsection{What the work does not show}

The paper is explicit, and so should you be when you teach it.

\begin{itemize}
\item That any real guard satisfies its contract.
\item That any agent became safer. No LLM was used.
\item That practitioners find the output useful. No user study.
\item That the model covers every real stack: rewriting, voting, loops and temporal session properties are outside the language.
\item That the experiments generalize: the corpus is one framework's examples; designs were modelled by one person.
\end{itemize}

\subsection{Open problems the paper names}

\begin{itemize}
\item Port the proofs to a proof assistant (Lean, Coq, Isabelle).
\item Add \emph{rewriting stages} and \emph{session-level/temporal properties}.
\item Run the method with practitioners and a second modeller.
\item \emph{Discharge contracts for real guards} (the biggest gap).
\item \emph{Learn} obligations instead of declaring them (a direction suggested from related work on learning assumptions).
\item Characterize order effects beyond the cases of the Order theorem.
\end{itemize}

\subsection{A few quotable sentences}

\begin{quote}
``A stack can accept an unsafe action although every stage meets its contract, because a guarantee was relied on where its assumption had not been established.''

\medskip
``Evidence for a contract belongs to one invocation of a stage. There is one way for evidence to move forward: a gate whose contract applies can \emph{provide} a fact that later stages may use. A guard's verdict provides nothing.''

\medskip
``The approach does not show that any guard meets its contract. It lists the claims an assurance argument rests on and tests which are needed.''
\end{quote}
