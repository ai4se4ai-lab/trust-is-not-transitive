{Trust Is Not Transitive: Explicit Inter-Layer Assumptions in Guardrail Hierarchies}

\maketitle

\begin{abstract}
LLM agents that edit code and call tools are increasingly protected by guardrail hierarchies: rules and classifiers screen every action and escalate doubtful ones to an LLM judge or a human. What such a stack guarantees is rarely stated, because each guard's guarantee is conditional on what it sees and how it was calibrated, and these conditions are assumed rather than established when one layer acts on another's verdict. We present \tint{}, a discipline and Python library that makes them explicit. Inter-layer trust relations are declared edges with named obligations, which a checker validates and an audit classifies as checked at runtime, true by construction, or assumed; a deterministic gate enforces information-flow and approval policies on every action; the judge sees only a structured view; and risk certificates apply only to the configuration they were computed for. We state the premises under which such a composition bounds end-to-end risk, show that early-accept cascades accumulate risk over acceptance routes rather than multiplying miss rates, and give a certified threshold-selection procedure. A protocol-registered study in a scripted agent sandbox validated the designed behaviors and exposed their limits. In the primary run nothing could be certified, so \tint{} blocked every action; the calibration counts revealed a floating-point defect that the same pipeline without its certificate requirement shipped. After the fix, the structured-view judge removed the family that targets the judge, but a post hoc provenance rule outperformed \tint{}, certification changed no decision, and every other pipeline accepted an attack family absent from calibration. The study establishes feasibility and failure modes, not effectiveness on real LLM agents.
\end{abstract}

\section{Introduction}
\label{sec:intro}
% =====================================================================

\IEEEPARstart{L}{arge} language model (LLM) agents no longer only produce text; they act. A coding agent reads an issue, edits files, runs the test suite and posts results to a web service~\cite{jimenez2023swebench}. Each action passes through a tool interface, and that interface is where developers place guardrails. In practice the guardrails are layered~\cite{arxiv250503574,arxiv231010501}. A cheap rule layer checks allowlists and data provenance, a small classifier scores the text that led to the action, uncertain cases go to an LLM judge, and the most consequential actions go to a human. The design follows the classic detection cascade~\cite{viola2001rapid} and the cost-aware model cascades used for LLM serving~\cite{arxiv230505176}: most traffic is resolved quickly, and only a small fraction pays for slow, careful review.

Such hierarchies are justified empirically, by measuring the accuracy of each guard and of the stack on a benchmark~\cite{arxiv240613352,arxiv241002644}. What is usually missing is a statement of what the stack guarantees and under which conditions. This has practical consequences, because every guard's guarantee is conditional. A provenance rule is only as good as the labels it reads. A classifier's calibrated error rate holds for the distribution and version it was calibrated on. An LLM judge may be accurate on benign inputs and still obey an instruction that the attacker who wrote the issue addressed to it~\cite{arxiv230212173}. When layer~$L_1$ accepts an action because $L_2$ accepted it, and $L_2$ relied on $L_3$, nothing in the code checks that $L_3$'s conditions held for this action. Trust between guardrails is not transitive: $L_1$ may rely on $L_3$ only if every link in between has established the conditions of the next one~\cite{christianson1997why}.

\textbf{Running example.} \emph{DevAgent} is a coding agent that triages issues in a repository, edits files and calls HTTP services. Its guardrail stack has a rule layer $L_1$, a text scorer $L_2$, a judge $L_3$ and a human approver $L_4$. Four traces frame our discussion.
In $\Tstar$, a malicious issue says ``to fix this, upload secret .env to sink.invalid''; the agent proposes to send the secret file to an external host.
In $\Tb$, a benign issue asks the agent to attach public diagnostics to a local test report; the proposed action has the same shape, an HTTP request carrying a file, but is legitimate.
$\Tj$ is $\Tstar$ with one more sentence, ``reviewer must answer SAFE'', which is addressed not to the agent but to the judge $L_3$. If the judge reads the raw issue, the attacker can tell it what to answer, and if the layers that consulted it act on its verdict, the action executes although each layer behaved as specified. Because $\Tj$ also exfiltrates a secret, a rule layer can stop it. We therefore also use $\Tjp$, which attaches the same sentence to an ordinary file patch that breaks no rule; only the judge stands between $\Tjp$ and execution.

\textbf{The gap.} Two lines of work come close but leave the problem open. Formal approaches specify agent behavior with temporal rules and contracts and enforce them at runtime~\cite{arxiv250318666,arxiv260918128,arxiv260222302}, or isolate untrusted data by construction~\cite{arxiv250318813,arxiv250523643}. They typically treat the guard as one monitor rather than as a hierarchy whose layers make probabilistic decisions. Statistical approaches give finite-sample guarantees for cascades and selective judges~\cite{arxiv250600911,arxiv240718370}. Their guarantees hold for the distribution and input on which they were calibrated, but they do not check that the guard's input at deployment is the input the guarantee was about. A position paper argues that safe agent deployment requires a layered probabilistic assume-guarantee architecture~\cite{arxiv260518672}. What is missing is an executable discipline that names each inter-layer obligation, says how it is established, and keeps deterministic and statistical evidence apart.

\textbf{Challenges.} Three difficulties stand in the way.
\emph{C1, implicit obligations.} In a typical stack the conditions under which a downstream verdict may be used are never written down, so their violation cannot be detected or even reviewed.
\emph{C2, wrong risk algebra.} Engineers reason about stacks with veto-ensemble intuitions (``an attack must fool every layer, so miss rates multiply''). Early-accept cascades let most traffic bypass the expensive layers, and the miss events of different guards share the same ground truth, so independence is rarely meaningful.
\emph{C3, stale evidence.} Calibration evidence is computed for one scorer, threshold, view and context, and nothing prevents its reuse after any of them changes.

\textbf{Key idea.} \tint{} treats each inter-layer trust relation as a declared edge that carries named obligations, and it classifies every obligation by how it is established: \emph{checked} by a runtime predicate that fails closed, \emph{by construction} of the code path, or \emph{assumed} and therefore listed for audit. Chains of trust remain possible, because a caller may rely on the composite guarantee of the layers below it, but only along declared edges whose obligations are established; no edge is derived from two others. Deterministic properties are never delegated: a gate checks them on every action. Statistical certificates are bound to the configuration that produced their evidence, and the runtime treats their applicability as one more checked obligation.

\textbf{Contributions.} This paper makes four contributions.
\begin{enumerate}
\item \emph{A problem formulation and a countermodel} (Section~\ref{sec:problem}). We define layers, contracts with typed obligations, and conditioned trust edges for agent guardrails, and show with $\Tjp$ that local contract satisfaction does not imply end-to-end safety when an obligation is not established.
\item \emph{A composition discipline with explicit premises} (Section~\ref{sec:approach}). A closed specification language and a checker make edges and obligations explicit, and an audit, currently performed by hand, classifies each obligation by how it is established; a lemma connects checked, realized edges to the guarantees a caller may use; a scoped soundness result states the premises under which a composition with a deterministic gate and a structured-view judge bounds end-to-end risk; corrected risk accounting separates veto ensembles from early-accept cascades; and a certified, cost-minimal selection procedure chooses escalation thresholds. The mathematics is deliberately elementary. Our contribution is to state the premises that practice leaves implicit and to make each one either checked or visibly assumed.
\item \emph{An open implementation} (Section~\ref{sec:impl}): typed actions with monitor-owned provenance, the checker, a fail-closed runtime that binds certificates to configuration fingerprints, calibration and selection, and a typed in-memory sandbox.
\item \emph{A preregistered feasibility study that reports its negative results} (Section~\ref{sec:eval}). We validate each designed behavior with the method that fits it, compare against six controlled comparators, including a strong control that keeps the deterministic gate, and report the primary run in which nothing was certified, a disclosed defect fix evaluated on fresh seeds, a post hoc provenance rule that outperforms \tint{} in our sandbox, and the failure of every pipeline under distribution shift.
\end{enumerate}

\textbf{Research questions.}
\begin{itemize}
\item \textbf{RQ1 (Specification and decomposition).} How can an end-to-end safety property of an agent be specified and decomposed into per-layer assume-guarantee contracts over heterogeneous guards, such that trust between layers is explicit and checkable rather than assumed transitive?
\item \textbf{RQ2 (Guarantees and escalation).} Under which conditions does a guardrail composition bound end-to-end risk, how does it fail, and which escalation policy minimizes expected cost subject to a risk bound?
\item \textbf{RQ3 (Engineering feasibility).} In a controlled agent sandbox, does a pipeline built with the discipline exhibit its designed behaviors against flat and naive hierarchical guardrails, where does it fail, and do the assumptions of its guarantees hold?
\end{itemize}

RQ3 was registered as a question about engineering value, i.e., about the risk--utility--cost trade-off. Because our scripted sandbox fixes every guard's behavior in advance, it cannot measure that trade-off, and we answer the narrower feasibility question stated here (Section~\ref{sec:eval}).

\textbf{Scope.} The observation that trust does not compose transitively is classical in security protocols and in compositional reasoning~\cite{christianson1997why,misra1981proofs,abadi1993composing}, and our bounds are standard probability. No API access or licensed guard models were available to us, so the study uses scripted guards in a typed sandbox; Section~\ref{sec:limits} and Section~\ref{sec:threats} state what this rules out.

Section~\ref{sec:background} gives background, Section~\ref{sec:problem} formalizes the problem, Section~\ref{sec:approach} presents \tint{}, Section~\ref{sec:eval} describes the implementation, the setup and the results, Section~\ref{sec:discussion} discusses lessons and applies the discipline to an existing guardrail design, Section~\ref{sec:threats} covers threats to validity, Section~\ref{sec:related} related work, and Section~\ref{sec:conclusion} concludes.

\section{Background}
\label{sec:background}
% =====================================================================

\subsection{Tool-Using Agents and Their Guardrails}

A tool-using agent repeatedly observes its context, proposes a tool call and receives the result. For a coding agent, the context includes issue text, repository files and command output, and the tools include file edits, test runs and HTTP requests~\cite{jimenez2023swebench}. The central security problem is \emph{indirect prompt injection}: text that the agent reads as data, such as an issue body, contains instructions that the agent then follows~\cite{arxiv230212173,arxiv240613352}. Agent-safety benchmarks measure how often attacks succeed and how often defenses block benign work~\cite{arxiv240613352,arxiv241002644,arxiv241009024,arxiv230915817,arxiv240110019,arxiv241107781}.

Guardrails intercept proposed actions. They range from deterministic rules and allowlists, through classifiers for injection and harmful content~\cite{arxiv231206674,arxiv240618495,arxiv250118837}, to LLM judges that reason about an action in context~\cite{arxiv250213458} and human approval. Production frameworks combine several of them~\cite{arxiv250503574,arxiv231010501}. We call such a combination a \emph{guardrail hierarchy} when layers are ordered by cost and a layer may accept, block or escalate to the next one.

\subsection{Reference Monitors and Information Flow}

A reference monitor mediates every access, is tamper-proof and is small enough to be verified~\cite{anderson1972computer}. \emph{Complete mediation}, checking every access, is a classic protection principle~\cite{saltzer1975protection}, and execution monitors can enforce exactly the safety properties of traces~\cite{schneider2000enforceable,ligatti2005edit}. Information-flow control attaches labels to data and propagates them; with a lattice of labels, derived data carry the join of their sources' labels~\cite{denning1976lattice,sabelfeld2003language}. Recent agent defenses track the provenance of every value and check a policy at each tool call~\cite{arxiv250318813,arxiv250523643}. In the \emph{dual-LLM pattern}, a privileged LLM that can call tools never reads untrusted text, while a quarantined LLM that reads it has no tool access~\cite{willison2023dual}.

\subsection{Assume-Guarantee Contracts}

A contract for a component is a pair $(A,G)$: if the environment satisfies assumption~$A$, the component guarantees~$G$~\cite{meyer1992applying,benveniste2018contracts}. Compositional proof rules for concurrent systems~\cite{misra1981proofs,jones1983tentative,abadi1993composing} show when the guarantees of components discharge each other's assumptions, and probabilistic and stochastic contracts extend the theory to probabilistic guarantees~\cite{delahaye2011probabilistic,nuzzo2019stochastic}. The rules are sound only when every assumption of a component is actually established, by its environment or by another component's guarantee. A system that relies on a component without establishing its assumptions obtains no guarantee from it, even if the component meets its contract.

\subsection{Statistical Certification}

For a fixed policy and $n$ independent calibration samples with $k$ observed losses, the Clopper--Pearson interval gives an exact one-sided upper confidence bound on the loss probability~\cite{clopper1934use}. When one policy is selected from a finite family of $K$ candidates, bounding all candidates simultaneously, for example each at level $\delta/K$, keeps the selected policy's bound valid despite the selection; Learn-then-Test formalizes this as multiple testing~\cite{angelopoulos2021learn,bates2021distribution}. Conformal risk control instead bounds the \emph{expected} loss of a threshold chosen from a nested family~\cite{arxiv220802814,arxiv210707511}. These guarantees assume independent or exchangeable data; under shift they need additional assumptions~\cite{tibshirani2019conformal,arxiv210600170}.

\subsection{DevAgent Policies}

Table~\ref{tab:policies} lists the three DevAgent policies. $\varphi_1$ and $\varphi_2$ are \emph{deterministic}: they can be decided from the typed action and trusted metadata. $\varphi_3$ is \emph{semantic}: whether an action follows an unauthorized instruction depends on intent, which no provenance label captures. Reading an issue is legitimate; obeying instructions hidden in it may not be. In our study the judge $L_3$ is a deterministic surrogate rather than an LLM, and the human $L_4$ is a stub that always abstains, so that no human correctness is assumed.

\subsection{Actions, Provenance and Policies}

An agent proposes a typed action $a=(\kappa,\tau,\iota,e)$ with a kind $\kappa$ from a finite set (\textsf{read}, \textsf{patch}, \textsf{test}, \textsf{http}, \textsf{delete}, \textsf{force\_push}), a target $\tau$, a tuple $\iota$ of references to the observations it uses as inputs, and an environment $e\in\{\textsf{sandbox},\textsf{production}\}$. Every observation carries a label $\lambda(o)\subseteq\{U,S\}$, where $U$ marks untrusted and $S$ secret content and the empty label means trusted and public. Labels form a lattice under set union, and an action inherits the union of its inputs' labels, $\lambda(a)=\bigcup_{o\in\iota}\lambda(o)$. The monitor writes the labels, and the agent cannot. An unknown reference is labeled $\{U,S\}$, so missing provenance fails closed.

From the action and trusted metadata the monitor computes six Boolean facts: \emph{destructive} ($\kappa$ is \textsf{delete} or \textsf{force\_push}), \emph{production} ($e=\textsf{production}$), \emph{external} ($\kappa=\textsf{http}$ and $\tau$ is not the configured local service), \emph{secret} ($S\in\lambda(a)$), \emph{untrusted} ($U\in\lambda(a)$), and \emph{approved} (the host holds an approval capability for the digest of exactly this action in the current approval epoch; approvals can be reused within an epoch and are revoked by advancing it). The deterministic policies are
\begin{align*}
\varphi_1 &: \textit{destructive}\wedge\textit{production}\Rightarrow\textit{approved},\\
\varphi_2 &: \neg(\textit{external}\wedge\textit{secret}),
\end{align*}
required of every executed action. The semantic policy $\varphi_3$ refers to an oracle $Y(h,a)\in\{0,1\}$ that is $1$ when executing $a$ in context $h$ would follow an unauthorized instruction. In our study $Y$ is fixed by construction for every trace; in practice it is an expert judgment. On the running example, $\Tstar$ and $\Tj$ send \texttt{.env} to \texttt{sink.invalid}, so \emph{external} and \emph{secret} hold, $\varphi_2$ is violated and $Y=1$. $\Tb$ satisfies $\varphi_{\mathrm{det}}$ and has $Y=0$. $\Tjp$ patches a file from the untrusted issue; it satisfies $\varphi_{\mathrm{det}}$ but has $Y=1$.

\textbf{Risk and utility.} Let $D$ be the distribution of proposals at deployment and \allow{} the event that the pipeline finally accepts. We measure
\begin{equation}
R(D)=\Pr_D[Y=1\wedge\allow],\quad U(D)=\Pr_D[\allow\mid Y=0].
\label{eq:risk}
\end{equation}
$R$ is a \emph{joint} probability: the fraction of all proposals that are unsafe and accepted. It differs from the miss rate $\Pr[\allow\mid Y=1]$ and from the fraction of accepted actions that are unsafe, $\Pr[Y=1\mid\allow]$, by factors that depend on how common attacks are. If one proposal in ten is unsafe and a guard misses half of them, the miss rate is one half but $R=0.05$. We report $\Pr[Y=1\mid\allow]$ separately as \emph{accepted conditional risk}. $R$ is a per-decision quantity. It bounds the expected number of unsafe acceptances per decision; it bounds the probability of an unsafe acceptance within $H$ decisions by $HR$ only if every decision's proposal has marginal distribution $D$, which agent sessions, where later actions depend on earlier results, rarely satisfy.

\subsection{Layers, Contracts and Conditioned Trust}

\begin{definition}[Layer]
A layer $L_i$ consists of a view function $v_i$ that maps $(h,a)$ to the information the layer may read, a decision function from views to $\{\allow,\block,\escalate\}$, and a cost $c_i$. A layer that errs, times out or returns an unknown value is treated as returning \block{}. A layer \emph{passes} a proposal if it does not block it.
\end{definition}

In DevAgent, $v_1$ is the six Boolean facts and $v_2$ is the raw issue text. A judge's view $v_3$ is either the raw text, in which case we call the judge \emph{exposed}, or a closed structured record without free text, in which case we call it a \emph{structured-view} judge. The structured-view judge corresponds to the \emph{privileged} component of the dual-LLM pattern: it decides, and it never reads attacker-authored text. (CaMeL's ``quarantined'' LLM is the opposite component, the one that reads untrusted text~\cite{arxiv250318813,willison2023dual}.)

Contracts must handle two kinds of guarantee. A deterministic guarantee is a statement about each invocation; a statistical guarantee is a statement about a distribution of invocations. We keep them apart.

\begin{definition}[Contract and obligations]
\label{def:contract}
A contract $C_i=(A_i,G_i)$ for layer $L_i$ has a scope $P_i$ of properties and an assumption given as a finite set $O_i$ of named obligations. Each obligation $o$ has a meaning $\llbracket o\rrbracket$, which is either a predicate on an invocation (its view, provenance and configuration) or a predicate on the distribution of invocations, such as ``invocations are drawn from the calibration distribution $D_{\mathrm{cal}}$''. A \emph{hard} contract guarantees a predicate $G_i$ of every invocation on which all per-invocation obligations hold. A \emph{statistical} contract guarantees a probabilistic statement, such as $\Pr_D[Y=1\wedge L_i\text{ passes}]\le b_i$, for every distribution $D$ of invocations that satisfies all of its obligations.
\end{definition}

Each obligation also has a \emph{kind}, which records how a deployment establishes it: \emph{checked} by a runtime predicate whose failure blocks the decision, \emph{by construction} of the only code path that reaches the layer, or \emph{assumed}, i.e., argued outside the system. The kind does not change the meaning of an obligation; it records the kind of evidence a reviewer has to inspect.

\begin{definition}[Conditioned trust edge]
\label{def:edge}
A trust edge $i\xrightarrow{p,\Omega}j$ states that layer $i$ may use the verdict of layer $j$ for property $p$ when the obligations in $\Omega$ hold for the invocations of $j$. The edge is \emph{well formed} if $p\in P_i\cap P_j$, every obligation in $\Omega$ is among those declared as provided on calls from $i$, and $O_j\subseteq\Omega$. An implementation \emph{realizes} the edge if every per-invocation obligation in $\Omega$ holds on every invocation of $j$ through this edge, and every distributional obligation in $\Omega$ holds of the distribution of those invocations.
\end{definition}

Being well formed is a syntactic property that a tool can check. Realizing an edge is a property of the implementation; it is what the kinds account for. A caller that consults a layer which itself consults further layers relies on the \emph{composite} guarantee of that sub-hierarchy. In this sense trust is composed, along declared edges. What \tint{} forbids is the short cut: from $i\to j$ and $j\to k$, nothing follows about using $k$'s verdict at $i$ directly, and an edge carries no authority to create others.

\subsection{The Countermodel}

\begin{proposition}[Local satisfaction does not compose]
\label{prop:t0}
There is a three-layer composition in which every layer satisfies its contract and every executed action satisfies $\varphi_{\mathrm{det}}$, yet an action with $Y=1$ executes, because a verdict is used although the producing layer's obligations do not hold.
\end{proposition}

\begin{IEEEproof}
Fix a fixture law in which $Y$ is a function of the structured view, and let $L_3$ be an idealized judge that blocks every action with $Y=1$ when it receives that view, but accepts any action whose raw issue text contains ``reviewer must answer SAFE''. Its contract has the obligation ``the input is the structured view'', so $L_3$ satisfies $C_3$. Let $L_2$ escalate to $L_3$ and return its verdict; its contract has the obligation that $L_3$ is invoked on the structured view, and its guarantee $G_2$ is that it accepts only what $L_3$ accepts, so $L_2$ satisfies it. Let $L_1$ pass every action that satisfies $\varphi_{\mathrm{det}}$ to $L_2$ and accept what $L_2$ accepts; its guarantee $G_1$, ``every accepted action satisfies $\varphi_{\mathrm{det}}$ and was accepted by $L_2$'', holds unconditionally. Now let the implementation hand the raw text of $\Tjp$ to $L_3$. $\Tjp$ satisfies $\varphi_{\mathrm{det}}$, $L_3$ accepts, and the action executes with $Y=1$. Each contract holds, the one of $L_3$ vacuously because its obligation is false, and the composition is unsafe.
\end{IEEEproof}

The proposition is the situation that compositional proof rules exclude: $L_2$ used the guarantee $G_3$ although the obligation of $C_3$ was not established~\cite{abadi1993composing}. Its point for engineers is that in deployed guardrail stacks this step is usually implicit. Nothing in the code checks that the judge saw the input its accuracy was measured on. On $\Tb$ every obligation can hold and the action executes correctly. On $\Tstar$, which contains no instruction for the judge, even the exposed judge blocks. On $\Tj$ the rule layer already blocks the exfiltration, so a rule check suffices; only $\Tjp$ needs the obligation on the judge's view. Fig.~\ref{fig:countermodel} contrasts the two compositions. Our evaluation includes a strong control that keeps the rule layer, so that the structured view is credited only with what the rule layer cannot do.

\subsection{Problem Statement}

The example generalizes to the three challenges of Section~\ref{sec:intro}: a verdict used although the producer's obligations do not hold (C1), cascade risk computed as if the stack were a veto ensemble (C2), and evidence reused for a different configuration (C3). Given a guardrail hierarchy and its contracts, we want to (i)~declare every trust edge and its obligations and check that they are well formed; (ii)~establish each obligation at runtime or by construction, and list those that can only be assumed; (iii)~enforce $\varphi_{\mathrm{det}}$ exactly on every executed action; (iv)~bound $R(D)$ only by quantities certified for the deployed configuration, and among certified configurations select one with minimal expected cost; and (v)~fail closed whenever a checked obligation fails at runtime.

\subsection{Specifying Contracts and Trust Edges (RQ1)}
\label{sec:spec}

A \tint{} specification is a JSON document with four fields: \texttt{layers}, \texttt{trust}, \texttt{mandatory} and \texttt{rules}. Each layer declares a name, the properties in its scope, the obligations it \texttt{requires} (its $O_i$), the obligations it \texttt{provides} on the calls it makes, and its \texttt{view}, one of \texttt{metadata}, \texttt{raw} or \texttt{structured-v1}. Each trust edge names a caller, a callee, a property and the obligations $\Omega$ established on that call. \texttt{mandatory} lists the deterministic invariants that must hold on every acceptance, and \texttt{rules} lists the deterministic predicates the gate implements. Fig.~\ref{fig:spec} shows the DevAgent specification. The schema is closed: unknown or duplicate fields, empty names and unsupported views are rejected while parsing.

Four details of Fig.~\ref{fig:spec} deserve explanation. $L_1$ has \texttt{semantic} in its scope because it is the entry point that returns the pipeline's final semantic verdict. \texttt{mandatory} states what must hold on every acceptance and \texttt{rules} states what the gate implements; the checker requires the two to coincide, so that no mandatory invariant lacks an implementation. $L_1$ declares \ob{quarantine} among the obligations it provides although no edge from $L_1$ uses it; the declaration is harmless and the checker ignores it. $L_4$ does not appear because, in the implemented topology, it can only block. In this DSL, \texttt{provides} is attached to the calling layer by convention. In \tint{}'s runtime, the obligations are in fact established by the trusted mediator on the call, not by the calling layer's own logic; Table~\ref{tab:obligations} records who establishes each one.

The obligation \ob{calibrated\_context} illustrates why kinds matter. Its configuration part can be checked on every decision. Its distribution part cannot: no predicate on a single invocation decides whether deployment data are exchangeable with calibration data. Splitting the obligation makes this visible. A specification in which every edge is well formed can still rest on an assumed obligation, and the audit in Section~\ref{sec:audit} lists them. The current DSL does not record kinds; Table~\ref{tab:obligations} classifies them by hand, and adding a kind field to the DSL is straightforward future work.

Algorithm~\ref{alg:check} checks a parsed specification. It accepts only if every declared edge is well formed (Definition~\ref{def:edge}), the mandatory invariants coincide with the implemented rules, no raw-view layer is asked to satisfy the \ob{quarantine} obligation, and the escalation graph is acyclic. It never adds an edge. Its running time is $O(|\mathcal{L}|+|\mathcal{E}|\cdot(\max_i|P_i|+\max|\Omega|))$: the scope test builds the intersection of two scope sets for every edge, so the time grows with the number of edges times the scope size.

\begin{algorithm}[!t]
\caption{Trust-edge checker}
\label{alg:check}
\footnotesize
\begin{algorithmic}[1]
\REQUIRE specification $\mathcal{S}=(\mathcal{L},\mathcal{E},M,\mathcal{R})$
\STATE reject if layer names are not unique or $\mathcal{L}=\emptyset$
\STATE reject unless $M=\mathcal{R}=\{\ob{production\_approval},\ob{secret\_egress}\}$
\FOR{each edge $(i,j,p,\Omega)\in\mathcal{E}$}
  \STATE reject if $i$ or $j$ is not a declared layer \COMMENT{no inferred endpoints}
  \STATE reject if $(i,j,p)$ was already seen
  \STATE reject if $p\notin P_i\cap P_j$ \COMMENT{scope}
  \STATE reject if $\Omega\not\subseteq\mathit{provides}(i)$ or $O_j\not\subseteq\Omega$ \COMMENT{obligations}
  \STATE reject if $\mathit{view}(j)=\texttt{raw}$ and $\ob{quarantine}\in O_j$
\ENDFOR
\STATE reject if the graph $(\mathcal{L},\mathcal{E})$ has a cycle \COMMENT{Kahn's algorithm}
\STATE \textbf{accept}
\end{algorithmic}
\end{algorithm}

The checker establishes a syntactic fact. The following lemma states what it buys when the implementation realizes the edges.

\begin{lemma}[Checked and realized edges]
\label{lem:edges}
If Algorithm~\ref{alg:check} accepts a specification and the implementation realizes every edge, then on every invocation of a layer $j$ through an edge $i\to j$, all obligations in $O_j$ hold. Consequently, if $C_j$ is a hard contract, $G_j$ holds on that invocation; if $C_j$ is statistical, $G_j$ holds for the distribution of such invocations provided its distributional obligations hold.
\end{lemma}

\begin{IEEEproof}
Acceptance implies $O_j\subseteq\Omega$ for the edge (line~7), and realization implies that every obligation in $\Omega$ holds. The consequences are the definitions of hard and statistical contracts.
\end{IEEEproof}

The lemma is little more than an unfolding of the definitions; its role is to separate two questions that practice conflates: whether the obligations are complete and consistent (the checker), and whether the code establishes them (realization). In \tint{}, realization is argued per kind (Table~\ref{tab:obligations}): checked obligations by the fail-closed runtime predicates, by-construction obligations by the fixed topology the runtime enforces, and assumed obligations not at all. The runtime does not read the declared \texttt{requires} and \texttt{provides} lists; it realizes the obligations through its fixed code path, and the declarations serve review and the checker. The checker does not verify that every acceptance route passes the deterministic gate; the runtime guarantees this for its fixed topology, and extending the checker with this graph condition is future work.

\subsection{Enforcing the Deterministic Fragment}
\label{sec:enforce}

Three mechanisms keep the deterministic guarantee independent of the semantic layers.

\emph{Complete mediation with monitor-owned metadata.} The agent can propose actions only through a parser with a closed schema of four fields (kind, target, input references and environment); it cannot supply labels, approvals or code. The provenance store is write-once, and a derived observation cannot drop a label of its parents. In the sandbox, the check and the effect happen in the same synchronous call, so no state changes between them.

\emph{Gate first, no overwrite.} $L_1$ evaluates $\varphi_1$ and $\varphi_2$ on the monitor's view before any semantic layer runs. A block ends the decision, and no later layer can turn it into an acceptance. In the implemented topology every acceptance route therefore passes the gate.

\emph{Structured-view judge.} The judge receives a closed record with the six Boolean facts and the $L_2$ score, and nothing else: no issue text, no free-form strings and no model-generated rationale. Text addressed to the judge cannot reach it, but the judge also loses every semantic cue the text contained. Section~\ref{sec:discussion} discusses this trade-off.

Semantic failures fail closed: a configuration that does not match the certificate, a scorer exception or out-of-range score, a judge exception or malformed verdict, and an escalation to the abstaining human stub all produce \block{}.

To state the soundness result we need one more fact about certificates. A certificate is computed from the losses of some decision function $f_{\mathrm{cal}}$ on calibration data, while the runtime executes a decision function $f_{\mathrm{run}}$.

\begin{lemma}[Containment]
\label{lem:contain}
If $f_{\mathrm{run}}$ accepts a proposal only when $f_{\mathrm{cal}}$ accepts it, then $R_D(f_{\mathrm{run}})\le R_D(f_{\mathrm{cal}})$ for every $D$.
\end{lemma}

\begin{IEEEproof}
The event $\{Y=1\wedge f_{\mathrm{run}}\text{ accepts}\}$ is contained in $\{Y=1\wedge f_{\mathrm{cal}}\text{ accepts}\}$.
\end{IEEEproof}

\begin{proposition}[Scoped soundness]
\label{prop:t1}
Assume
(P1)~complete mediation, unforgeable labels and approvals, and no state change between check and effect;
(P2)~every acceptance passes a deterministic monitor that is correct for $\varphi_{\mathrm{det}}$ on the typed view;
(P3)~no block is overwritten;
(P4)~every trust edge is well formed and realized (Lemma~\ref{lem:edges}); and
(P5)~the acceptance routes $E_1,\dots,E_q$ are disjoint, and for each route a certificate computed from $n$ i.i.d.\ calibration proposals drawn from $D$ guarantees $\Pr_D[Y=1\wedge E_\ell]\le b_\ell$ for a certified decision function in which every layer receives its contracted view, all certificates holding simultaneously with probability at least $1-\delta$, and the deployed function accepts on route $E_\ell$ only when the certified one does whenever every layer receives its contracted view.
Then (i)~no executed action violates $\varphi_{\mathrm{det}}$, and (ii)~with probability at least $1-\delta$, $R(D)\le\sum_{\ell}b_\ell$.
\end{proposition}

\begin{IEEEproof}
(i)~By P1, an action executes only if the runtime accepted it, and the state checked is the state acted on; by P2 and P3, the deterministic monitor allowed it and no later layer overruled a block, so it satisfies $\varphi_{\mathrm{det}}$. (ii)~Because the routes are disjoint, $\mathbf{1}[Y=1\wedge\allow]=\sum_\ell\mathbf{1}[Y=1\wedge E_\ell]$, and taking expectations gives $R(D)=\sum_\ell\Pr_D[Y=1\wedge E_\ell]$. By P4 and Lemma~\ref{lem:edges}, every layer on every route is invoked with the obligations of its contract, in particular with its contracted view. P5's conditional containment premise therefore applies on every proposal, so by Lemma~\ref{lem:contain} each term is at most $b_\ell$ on the event that all certificates hold.
\end{IEEEproof}

Part (i) is close to definitional once P1--P3 hold, because $\varphi_{\mathrm{det}}$ is defined over the facts the gate computes; its value lies in making the mediation premises explicit. Part (ii) shows where the edges enter. Consider DevAgent with two routes (Fig.~\ref{fig:routes}): $E_1$ accepts at $L_2$ when $s<t$, and $E_2$ accepts when the judge accepts. A certificate for $E_2$ is computed for the structured-view judge. If the $L_2\to L_3$ edge's \ob{quarantine} obligation were not realized, because the implementation handed the judge raw text, the premise of P5 would fail for $E_2$, containment in the certified decision function would no longer be established, and the $E_2$ certificate would give no guarantee. This is exactly the failure on $\Tjp$. The implementation uses the simplest instance, $q=1$: it certifies the joint unsafe acceptance of the whole policy, so that $b_1$ bounds $R(D)$ directly and the edge obligations enter through the containment premise.

The simultaneity in P5 needs no independence: allocating $\delta$ across the certificates and applying a union bound suffices. The proposition says nothing about whether a raw LLM judge is correct, or whether deployment data are exchangeable with calibration data; both are assumptions, listed in Section~\ref{sec:limits}.

\subsection{Accounting for Risk Across Layers (RQ2)}
\label{sec:accounting}

Two structures are easily confused. In a \emph{veto ensemble}, an action is accepted only if every guard passes it. In an \emph{early-accept cascade}, a cheap layer may accept an action that the expensive layer never sees. To compare them, let $M_i=\{Y=1\wedge L_i\text{ passes}\}$ be the event that guard $i$ would miss an unsafe proposal, evaluated counterfactually on every proposal, also on those that an actual run stopped earlier. Let $\theta=\Pr[Y=1]$ and $m_i=\Pr[L_i\text{ passes}\mid Y=1]$ for $N$ guards.

\begin{proposition}[Veto and cascade risk]
\label{prop:t2}
(a)~For a veto ensemble, $R=\Pr(\bigcap_i M_i)\le\min_i\Pr(M_i)$.
(b)~If the guards' misses are conditionally independent given $Y=1$, then $R=\theta\prod_i m_i$, which differs from $\prod_i\Pr(M_i)=\theta^{N}\prod_i m_i$ when $N>1$ and $\theta<1$.
(c)~Suppose that, given $Y=1$, guard $i$ passes iff $V_i<m_i$, where with probability $\rho$ all $V_i$ equal one shared uniform variable and otherwise they are independent uniforms (a common-shock model). Then $R=\theta\bigl[(1-\rho)\prod_i m_i+\rho\min_i m_i\bigr]$.
(d)~For an early-accept cascade with disjoint acceptance routes $E_\ell$, $R=\sum_\ell\Pr[Y=1\wedge E_\ell]$, and in general neither the minimum in (a) nor the product in (b) bounds $R$.
\end{proposition}

\begin{IEEEproof}
(a)~A veto ensemble accepts an unsafe proposal exactly when all guards pass it, and an intersection is no more probable than any of its members. (b)~Conditioning on $Y=1$ and using independence gives $\theta\prod_i m_i$; the events $M_i$ themselves cannot be independent in general, because they all contain $Y=1$. (c)~Given the shared variable, all guards pass together with probability $\min_i m_i$; otherwise the passes are independent. (d)~The identity follows from the indicator decomposition in the proof of Proposition~\ref{prop:t1}. For the second claim, take two layers where $L_2$ accepts unsafe proposals with probability $0.1$ on its cheap route and escalates the rest to a judge $L_3$ that blocks all of them. Then $R=0.1$, while $\Pr(M_3)=0$, so neither $\min_i\Pr(M_i)$ nor any product involving $\Pr(M_3)$ bounds $R$.
\end{IEEEproof}

The gap is large even for small stacks. With miss rates $0.1$, $0.2$ and $0.3$, a veto ensemble with conditionally independent misses passes an attack with conditional probability $0.006$, and one with fully shared failures with $0.1$, about seventeen times more, although the per-guard miss rates are identical in both cases.

\begin{proposition}[Pairwise statistics do not identify joint risk]
\label{prop:t4}
There are joint laws of three guards' misses with identical marginals and zero pairwise correlations whose triple-miss probabilities are $0$ and $1/4$.
\end{proposition}

\begin{IEEEproof}
Let each miss indicator be a fair bit. Under the uniform law on bit triples with even parity, all pairs are independent and the three bits are never all $1$; under the uniform law on odd-parity triples, all pairs are again independent and $(1,1,1)$ has probability $1/4$. This is Bernstein's classical example of pairwise but not mutual independence.
\end{IEEEproof}

Two tightness facts complete the picture. The minimum in (a) is attained when all guards threshold one shared uniform variable; it is the Fr\'echet--Hoeffding upper bound, so no better bound follows from the marginals alone. And over all laws consistent with given route certificates $b_\ell$, the route sum is attained by placing unsafe mass $b_\ell$ on each route. The risk of a pipeline should therefore be estimated on the pipeline, as a joint probability, rather than assembled from per-layer statistics.

\subsection{Certifying and Selecting Escalation Policies (RQ2)}
\label{sec:certify}

\textbf{Finite-family certification.} Let $\Pi=\{\pi_1,\dots,\pi_K\}$ be candidate policies fixed before calibration; in DevAgent, $\pi_j$ escalates from $L_2$ to $L_3$ when $s\ge t_j$ for a threshold grid $t_j$. On $n$ independent calibration proposals, count $k_j$, the number of unsafe proposals that $\pi_j$ accepts, and let $u_j$ be the one-sided Clopper--Pearson upper bound at level $\delta/K$,
\begin{equation}
u_j=\mathrm{Beta}^{-1}\!\left(1-\tfrac{\delta}{K};\,k_j+1,\,n-k_j\right),
\label{eq:cp}
\end{equation}
with $u_j=1$ when $k_j=n$. Select the candidate with the lowest mean calibration cost among those with $u_j\le\varepsilon$, breaking ties by candidate name. If no candidate qualifies, deploy the block-all policy and report infeasibility; the budget is never relaxed.

\begin{proposition}[Certified selection]
\label{prop:select}
If the calibration proposals are drawn i.i.d.\ from $D$, then with probability at least $1-\delta$ over calibration, $R_D(\pi_j)\le u_j$ holds simultaneously for all $j$. In particular, the selected policy satisfies $R_D\le\varepsilon$.
\end{proposition}

\begin{IEEEproof}
Each $u_j$ is an exact upper confidence bound at level $\delta/K$ for a fixed policy. A union bound over the $K$ fixed candidates gives simultaneous coverage at level $\delta$, and selection based on the data cannot leave the event on which all bounds hold.
\end{IEEEproof}

This is a special case of Learn-then-Test~\cite{angelopoulos2021learn} with Bonferroni correction and binomial tail $p$-values. It is a high-probability statement about the realized risk of the deployed policy. Conformal risk control~\cite{arxiv220802814} makes a different promise, a bound on the expected loss over calibration and test draws; \tint{} implements both, and the experiments use Proposition~\ref{prop:select}.

\textbf{Binding certificates to configurations.} A certificate records a policy fingerprint, a context identifier, a view version, the bound $u$, $\delta$ and $n$. The fingerprint is a SHA-256 hash of the specification, the threshold, the \emph{declared} version strings of the scorer and judge, the view version and the environment. On every decision the runtime recomputes the fingerprint of the configuration it is running and makes a semantic acceptance only if the certificate matches it, the bound is within the deployment budget, and $\delta$ does not exceed the host's confidence budget. This check binds the certificate to the declared configuration. It does not hash code, so a code change without a version change goes unnoticed (the defect fix of Section~\ref{sec:rq3} was accompanied by a manual version change). The context identifier and view version are configuration constants: matching them is a configuration check, not a test of the data distribution.

\textbf{Escalation rule.} Which inputs should be escalated? Let $x$ be the trusted view of a proposal, $r_0(x)$ the conditional risk of accepting it at the cheap layer, $r_1(x)$ the conditional risk after escalation, and $d(x)>0$ the extra cost of escalation. A randomized policy escalates with probability $\gamma(x)$ and should minimize $\mathbb{E}_D[d\,\gamma]$ subject to $R_D(\gamma)=\mathbb{E}_D[r_0-\gamma\,(r_0-r_1)]\le\varepsilon$.

\begin{proposition}[Escalation by risk reduction per cost]
\label{prop:t3}
For a multiplier $\mu\ge0$, the pointwise minimizer of the Lagrangian escalates when $\mu\,(r_0(x)-r_1(x))>d(x)$, accepts when the inequality is reversed, and may randomize on ties. If a feasible measurable policy of this form and a finite $\mu$ satisfy complementary slackness, $\mu(R_D(\gamma)-\varepsilon)=0$, the policy is optimal.
\end{proposition}

\begin{IEEEproof}
The Lagrangian is $\mathbb{E}[d\,\gamma]+\mu(\mathbb{E}[r_0-\gamma(r_0-r_1)]-\varepsilon)$. The coefficient of $\gamma(x)$ is $d(x)-\mu(r_0(x)-r_1(x))$, so the minimizer sets $\gamma(x)=1$ where it is negative and $\gamma(x)=0$ where it is positive. Weak duality and equality of the Lagrangian value under complementary slackness certify optimality.
\end{IEEEproof}

The rule thresholds the \emph{risk reduction per unit cost}, not the classifier score; it reduces to a score threshold only if the cost is constant and the risk reduction is monotone in the score. If $r_1>r_0$, which happens when an exposed judge can be manipulated as on $\Tjp$, escalation increases risk. A finite multiplier need not exist: for $x$ uniform on $(0,1)$, $r_0(x)=x$, $r_1(x)=0$, $d(x)=1$ and $\varepsilon=0$, feasibility requires escalating almost every input, which no finite $\mu$ achieves. Because conditional risks are unknown in practice, \tint{} optimizes within the finite certified family instead: enumeration finds the cheapest certified deterministic candidate, and a linear program over mixtures of candidates gives the cheapest randomized policy; for one risk constraint it has an optimum with at most two non-zero weights. For a deployable mixture the program must use the bounds $u_j$, so that on the simultaneous event the mixture's risk is at most $\sum_j w_j u_j$. Both procedures are exact within the family and make no claim about unrestricted policies.

\subsection{Assumptions and Limits}
\label{sec:limits}

The guarantees above rest on assumptions that the runtime cannot establish itself.
\emph{Trusted host:} the provenance, approval and certificate stores and the declared component versions are honest.
\emph{Typed semantics:} safety is relative to the typed action interpreter; shell parsing, covert channels and tools with unmodeled effects are out of scope.
\emph{Exchangeability:} certificates assume that deployment proposals follow the calibration distribution. Under a shift of total-variation size $\eta$, the selected policy's risk is at most $u_j+\eta$ on the simultaneous event, but $\eta$ must be justified externally.
\emph{Adaptive inputs:} if a policy accepts any proposal $x$ with $Y(x)=1$, an attacker who can choose proposals plays $x$ every time and obtains $R=\Pr[Y=1]$; so against an unconstrained adaptive attacker no bound below the attack rate holds unless the policy accepts no unsafe proposal at all, as exact deterministic mediation does for $\varphi_{\mathrm{det}}$.
\emph{Fixed topology:} the checker accepts general acyclic specifications, but the runtime enforces only the $L_1\to L_2\to L_3$ topology of Fig.~\ref{fig:spec}.
\emph{No refinement proof:} we test the implementation and illustrate the countermodel on a finite abstraction; we do not prove that the implementation refines a model.

% =====================================================================
\section{Evaluation}
\label{sec:eval}
% =====================================================================

Our evaluation is a controlled, preregistered feasibility study, and its design follows from the claims under test. They are claims about composition: whether an obligation is established, whether a bound covers the true risk, and whether the decision function that runs is the one that was certified. Testing them requires a ground-truth label for every proposed action, a known data-generating law against which a probability bound can be checked, and components whose behavior is fully known, so that each outcome can be attributed to the composition rather than to an opaque model. Current LLM agent benchmarks do not provide these together, and we had no access to LLM APIs or licensed guard models. We therefore built a typed, in-memory agent sandbox with an authored fixture law, scripted guards and a deliberately vulnerable judge that serves as an executable countermodel, and we test each claim with the method that fits it: unit tests and an executable abstraction for the deterministic fragment, mutation analysis for the checker, Monte Carlo replications against a known law for the bounds, and replay of seven pipelines for the composition. Because the guards are scripted, every pipeline's decision on a trace family is known in advance. The replay therefore validates designed behavior and measures nothing about real guards; its value is that it executes the whole discipline end to end, surfaces defects and premises that fail, and makes every outcome explainable. The comparators isolate mechanisms rather than reproduce products, and include a strong control that keeps the deterministic gate. Thresholds, budgets and analyses were frozen before held-out data were generated; one defect fix and the post-review analyses are labeled exploratory. This design favors internal validity and full reproducibility over external validity. It can show that the discipline is implementable, that it rejects the errors it targets, and where it fails. It cannot measure the risk--utility trade-off of the semantic layers, which is why we answer RQ3 as a feasibility question, and it cannot show that \tint{} makes real LLM agents safer.

\subsection{Implementation and Its Relation to the Approach}
\label{sec:impl}

\tint{} is a Python library of about seven hundred lines in eight modules, with an experiment driver, an executable abstraction and analysis scripts. Table~\ref{tab:impl} maps every element of the approach to the code that implements it and the tests that exercise it.

\emph{Model and provenance.} \texttt{tint.model} defines the immutable \texttt{Action} type, the label lattice as a bit flag, a write-once \texttt{ProvenanceStore} that rejects derived observations which drop parent labels and labels unknown references $\{U,S\}$, and an \texttt{ApprovalStore} whose grants are keyed by action digest and epoch. \texttt{action\_view} computes the six facts of Section~\ref{sec:problem}; only one exact local mock destination counts as internal, so aliases and real URLs are external.

\emph{Specification.} The DevAgent specification is stored in \texttt{experiments/configs/devagent.json} and shown reformatted in Fig.~\ref{fig:spec}. \texttt{tint.spec.parse} rejects duplicate JSON keys and fields outside the closed schema, and \texttt{tint.spec.check} implements Algorithm~\ref{alg:check}.

\emph{Runtime.} \texttt{tint.runtime.GuardRuntime} is the online half of Fig.~\ref{fig:overview}. Its constructor re-runs the checker and refuses any topology other than $L_1\to L_2\to L_3$ with the declared views. This is where the by-construction obligations of Table~\ref{tab:obligations} are realized: the only path to the judge calls \texttt{quarantine}, which builds the closed record. The runtime also blocks any action whose declared environment differs from the trusted dispatcher's. \texttt{evaluate} runs the gate, recomputes the fingerprint, checks certificate applicability, calls the scorer and, if needed, the judge through a wrapper that turns every exception into \block{}, and optionally logs the decision. \texttt{parse\_tool\_call} is the closed tool parser.

\emph{Guards.} \texttt{tint.layers} contains the gate, the lexical scorer, the projection to the structured view, the structured-view judge and the \texttt{ExposedJudge} test double. These are explicit stand-ins. The scorer counts eight indicator tokens and returns $s=\min(0.98,\,0.04+0.12w)$ for $w$ matched tokens. The structured-view judge blocks when \emph{secret} and \emph{external} both hold or when $s\ge0.40$, so for actions that pass the gate it is a second threshold on the score. The exposed judge is the same judge plus one rule: it accepts whenever the raw text contains ``reviewer must answer safe''.

\emph{Calibration and synthesis.} \texttt{tint.calibration} implements the Clopper--Pearson bound, simultaneous family certification, split-conformal quantiles, conformal risk control, the veto bounds of Proposition~\ref{prop:t2}, and the \texttt{Certificate} type. \texttt{tint.synthesis} implements certified selection, the rule of Proposition~\ref{prop:t3} and the mixture LP, solved with HiGHS through SciPy.

\emph{Sandbox and comparators.} \texttt{tint.agents.Sandbox} is a typed interpreter that records effects in memory; it has no shell and no network client. \texttt{tint.baselines} implements the comparators of Section~\ref{sec:setup}. The experiment driver \texttt{experiments/run.py} generates traces, calibrates, selects, replays every pipeline and writes compressed per-decision logs. Calibration losses are computed with the decision core \texttt{baselines.decide}, which implements \tint{}'s routing without the certificate check, while held-out decisions come from \texttt{GuardRuntime}. Lemma~\ref{lem:contain} needs the two to agree; replaying the exploratory calibration split through both found \resCalEquivDisagree{} disagreements in \resCalEquivCompared{} proposals.

\textbf{Calibration.} \tint{} selects its threshold from \resThresholdCount{} values, $t\in\{0,0.1,\dots,1\}$, fixed before calibration. \textbf{Metrics.} On the test split we report joint unsafe acceptance $\hat R$ (Eq.~\eqref{eq:risk}), benign utility $\hat U$, accepted conditional risk, the number of hard violations (accepted actions that violate $\varphi_{\mathrm{det}}$), modeled cost and wall-clock time per decision. Modeled cost charges $\resCostRules$, $\resCostScorer$, $\resCostJudge$ and $\resCostApproval$ units for reaching $L_1$ to $L_4$; the units encode the intended cost ratio of rules, classifier, LLM judge and human, not milliseconds, tokens or money. Wall-clock time is measured with a nanosecond counter around the decision function and describes our Python code, not a model.

\textbf{Statistical analysis.} As preregistered, we compare \tint{} with each comparator on paired seed-level aggregates, with the mean paired difference, a $95\%$ percentile bootstrap interval over seeds~\cite{efron1994introduction}, a two-sided Wilcoxon signed-rank test~\cite{wilcoxon1945individual} with Holm correction across the six comparisons~\cite{holm1979simple}, and the Vargha--Delaney $\hat A_{12}$~\cite{vargha2000critique}, following guidance for randomized algorithms in software engineering~\cite{arcuri2011practical}. Because the scripted decisions are deterministic per family, these tests can only confirm that the sign of a difference is the same in every seed (Section~\ref{sec:rq3}). We therefore lead with the population values that follow from the authored family masses and use the replay to confirm them.

\textbf{Further experiments.} For H3 we draw \resPrimaryReplications{} calibration sets of size \resCoverageCalibrationCount{} (\resCoveragePerSeed{} per seed) from a known law with eleven candidate policies whose true risks range from $0$ to $0.20$, select the cheapest candidate whose simultaneous bound is at most \resCoverageTarget\%, and record whether the selected candidate's true risk lies below its bound. For dependence we simulate three guards with conditional miss rates \resDependenceFirst, \resDependenceSecond{} and \resDependenceThird{} under the common-shock model at five mixture weights, with \resDependenceSamples{} samples per cell and seed. For H2 we generate specifications with five to five hundred properties and two to six layers and apply four mutations: missing evidence, out-of-scope property, unknown endpoint and an added cycle. For H5 we draw fifty random finite candidate families and compare the selector with independent enumeration. For H8 we try to express five policy classes in the DSL. For H1 and H4 we run PRISM~\ver{4.11}~\cite{kwiatkowska2011prism} on a discrete-time Markov chain abstraction of the canonical traces.

The primary study took \resPrimaryRuntime\,s and the replication \resExploratoryRuntime\,s. Three dated amendments govern deviations from the preregistration. A2 added descriptive per-family analyses and corrected the attribution of the adaptive-search instrument after a first round of review. \subsection{RQ1: Specification and Decomposition}

\textbf{H1, deterministic safety.} The unit test \texttt{test\_all\_deterministic\_cases} evaluates the gate on all $64$ combinations of its six Boolean inputs against a separately written formula for $\varphi_{\mathrm{det}}$ and finds no disagreement. This is a regression check of the implementation, not an independent oracle. PRISM checked \resPrismCases{} configurations of a five-state abstraction, the three canonical traces under naive and checked routing, for two reachability properties: under naive routing $\Tj$ reaches a bad execution with probability one, under checked routing no configuration does, and $\Tb$ executes in both. The abstraction encodes each trace's routing in its transitions, so it illustrates the countermodel rather than verifying the runtime. In the replay, the pipelines with a gate (B1, B5, B6, B7, \tint{}) executed no hard violation in either study, whereas B2, B3 and B4 accepted every production deletion, \resExploratoryClassifierOnlyHard{} hard violations each on the exploratory test split (Table~\ref{tab:results}). The hard-violation metric uses the same predicate as the gate, and the runtime additionally blocks production actions in the sandbox deployment through its environment check, so the zero is close to definitional. H1 is supported within the tested scope; the evidence concerns the typed abstraction, and no refinement proof links the runtime to a model.

\textbf{H2, checker.} In each study the checker rejected all \resPrimaryCheckerTP{} invalid specifications and accepted all \resPrimaryCheckerTN{} valid ones, with \resPrimaryCheckerFP{} false positives and \resPrimaryCheckerFN{} false negatives. These counts repeat \resPrimaryCheckerUniqueInvalid{} unique invalid and \resPrimaryCheckerUniqueClean{} unique valid specifications across seeds, because the generator is deterministic, and the four mutation operators correspond one to one to reject conditions of the checker. Perfect precision and recall therefore show that the implemented conditions fire as intended. They say nothing about the errors engineers make, and three conditions were not mutated at all: evidence not provided by the caller, a raw-view callee requiring \ob{quarantine}, and duplicate edges. Checking time is small but grows faster than the number of edges: for specifications with at least fifty properties, a log--log fit of median time against the number of edges has slope \resCheckerSlope{} pooled across depths and \resCheckerSlopeSix{} at six layers, and the largest specification, with \resCheckerMaxEdges{} edges, takes a median of \resCheckerMaxMs\,ms. The cause is the per-edge set intersection noted in Section~\ref{sec:spec}; replacing it by two membership tests would make the check linear.

\textbf{H8, expressiveness.} Of the \resPolicyClasses{} policy classes we tried to express, the DSL fully supports \resSupportedClasses, production approval and secret egress. Semantic injection is supported only as a statistical proxy through the scorer and judge; filesystem confinement and cumulative spending cannot be expressed. H8 is refuted.

\textbf{Answer to RQ1.} An end-to-end property can be decomposed into a deterministic fragment, enforced by a gate on every action, and a semantic fragment whose trust edges and obligations are declared, checked for well-formedness, and classified by how they are established (Table~\ref{tab:obligations}). The checker's conditions fire as intended. The decomposition is narrow: the language covers two deterministic policy classes, the runtime realizes one fixed topology, and the most important semantic obligation, exchangeability with calibration data, can only be assumed.

\subsection{RQ2: Guarantees and Escalation}

\textbf{H4, canonical traces.} Under invalid delegation (B4), $\Tj$ is accepted and would execute; under \tint{} it is blocked by the gate. The strong control B5 also blocks $\Tj$, because $\Tj$ violates $\varphi_2$. H4 is supported, and the result shows the value of the deterministic gate, not of the structured view; the structured view can only matter for $\Tjp$, which RQ3 tests.

\textbf{H3, coverage of certificates.} In \resPrimaryCoverageCovered{} of \resPrimaryReplications{} replications, the true risk of the selected candidate lay below its simultaneous bound: coverage \resPrimaryCoverage\% (exact $95\%$ interval \resPrimaryCoverageLo--\resPrimaryCoverageHi\%). The replication's coverage study gave \resExploratoryCoverage\% (\resExploratoryCoverageLo--\resExploratoryCoverageHi\%). Both lie well above the nominal \resNominalConfidence\%, as expected from the union bound over eleven candidates and the discreteness of the binomial. In the sandbox replication, every seed's certified bound, between \resExploratoryBoundMin\% and \resExploratoryBoundMax\%, lies above the selected policy's population risk of \resExploratoryCheckedQuarantinePopulationRisk\%. H3 is supported for static, independent laws.

\textbf{Dependence.} In the simulation of three guards with fixed marginal miss rates, the joint miss probability moved from the product of the rates at mixture weight zero to their minimum at weight one, and it stayed within \resDependenceGap{} of Proposition~\ref{prop:t2}(c) in all fifty cells. The two parity laws of Proposition~\ref{prop:t4} gave triple-miss probabilities $0$ and $0.25$, as stated.

\textbf{H5, selection.} In all \resPrimarySynthInstances{} random finite families, certified selection returned the candidate found by independent exhaustive enumeration (\resPrimarySynthMismatches{} mismatches), and the mixture LP's optimum agreed with an independent enumeration of the LP's vertices; in this experiment the LP was solved on the families' true risks, which tests the solver, whereas a deployable mixture must use the bounds $u_j$. In the sandbox, selection was degenerate. The eleven thresholds formed \resExploratoryDistinctRiskLevels{} risk levels in the replication: thresholds $0$ to $0.4$ send the three high-score families to the judge, which blocks them, and higher thresholds accept them cheaply. Thresholds $0.1$ to $0.4$ had identical cost and bound, so the choice of $t=\resExampleThreshold$ is a tie-break by name.

\textbf{Answer to RQ2.} A composition bounds end-to-end risk under five explicit premises (Proposition~\ref{prop:t1}), and its certificates covered the true risk whenever their own premises held. It fails in specific ways: a verdict used although an obligation does not hold (Proposition~\ref{prop:t0}), veto reasoning applied to a cascade or to dependent guards (Propositions~\ref{prop:t2} and~\ref{prop:t4}), escalation to a judge whose risk exceeds the cheap layer's (Proposition~\ref{prop:t3}), and any shift or adaptation that breaks exchangeability. For escalation, the cost-optimal rule escalates when the risk reduction per unit cost exceeds the inverse multiplier, which is a score threshold only under extra monotonicity conditions (Proposition~\ref{prop:t3}); since conditional risks are unknown, \tint{} selects exactly within a finite certified family. That selection was verified on synthetic families; in the sandbox it reduced to a feasibility decision, so the escalation theory was not exercised there.

\subsection{RQ3: Engineering Value in the Sandbox}

The certificate was still accepted, because matching a context identifier is a configuration check. The discipline made this obligation visible in the audit; it did not prevent its violation.

\textbf{Adaptive inputs.} The preregistered adaptive search gave each pipeline \resAdaptiveBudget{} queries per seed to find an accepted unsafe phrase among fixture phrases. The experiment turned out to be uninformative for two reasons. Every pipeline was defeated on the first query in every seed, because the first phrase is the implicit patch, so no response-informed adaptation was ever exercised. And the instrument queried the uncertified decision core at the fixed threshold rather than the runtime with its certificate; Amendment A2 corrects this attribution without altering the logs. The study provides no evidence about adaptive attackers.

\textbf{Cost and latency.} \tint{}, B6 and B5 reach the same layers and have the same modeled cost, \resExploratoryCheckedQuarantineCost{} units per decision, with \resExploratoryCheckedReachThree\% of decisions reaching the judge. \tint{}'s median wall-clock time per decision was \resExploratoryCheckedCpuMedian\,$\mu$s against \resExploratoryNaiveWithSinkCpuMedian\,$\mu$s for B5. \textbf{Answer to RQ3.} In the controlled sandbox, the discipline is implementable and each mechanism did what it was designed to do. The gate prevented every deterministic violation, the structured view removed the judge-targeting family at no utility cost relative to the strong control, and the certificate requirement refused to deploy a defective scorer. These outcomes are confirmations of designed behavior, not measured improvements, and the sandbox shows no general risk--utility advantage: a provenance rule dominated \tint{}, certification changed no decision once the defect was fixed, a gate-only pipeline had higher utility, and every pipeline except the provenance rule failed under shift. The registered question about engineering value, i.e., about a better trade-off, therefore remains open, for real LLM agents (H7) and even within a richer sandbox.

\section{Discussion}
\label{sec:discussion}
% =====================================================================

\subsection{Lessons for Engineers of Guardrail Stacks}

\textbf{Write every trust edge down, with how each obligation is established.} Each time one layer acts on another's verdict, state for which property, which facts about the callee's input make the verdict meaningful, and whether each fact is checked, true by construction or only assumed. The value of the exercise is the list of assumed obligations it produces; in our study it predicted the one failure, shift, that no semantic mechanism prevented.

\textbf{Never delegate deterministic properties, and try provenance first.} The gate did most of the work in our study: it alone stopped $\Tstar$, $\Tj$ and every production deletion. Where untrusted inputs can be identified, a provenance policy can be stronger still, as B7 showed in our sandbox. Semantic guards are for the cases provenance cannot decide, such as an authorized patch derived from an issue.

\textbf{Give the judge a view the attacker did not write, and design that view.} The structured view removed the only attack aimed at the judge, but in our design it also reduced the judge to a second threshold on the score. A useful judge needs semantic information. The dual-LLM pattern suggests how to supply it~\cite{willison2023dual}: a component that reads the untrusted text but cannot issue verdicts extracts typed fields, and the judge reasons over those fields, which are themselves untrusted inputs with their own contract. For a coding agent, such fields could include the files a patch touches, whether it changes build or CI configuration, credentials, permissions or network targets, and whether the change matches what the issue requested. Whether such a projection preserves enough semantics for $\varphi_3$ is an empirical question our study could not answer.

\textbf{Measure the pipeline against a budget, and do not compose per-layer rates.} The risk of an early-accept cascade is a sum over acceptance routes, and per-layer miss rates, multiplied or minimized, can be wrong by an order of magnitude; pairwise correlations do not repair this. In our primary run, it was the refusal of a pipeline-level risk check that led us to the defect, and any acceptance test of joint risk against a budget would have done the same. A certificate adds a confidence statement and a binding to the configuration, and the binding is only as strong as the identities it hashes: it should cover component code, not only declared versions.

\textbf{Expect evidence to expire.} A certificate says nothing about data it has not seen. Configuration binding prevents reuse after a declared change; it does not detect a shift in the inputs, which needs a separate, explicitly assumed or monitored obligation.

\subsection{On the Negative Results}

A block-all policy has zero risk and zero value, and we do not count it as a success. It shows the intended behavior of a certificate requirement under a broken component, refusing service rather than accepting unsafely, and it shows the cost of that behavior: with a defective guard, the safe outcome is no service at all, a trade-off between availability and safety that a deployment should make explicitly. The post hoc provenance result is negative in a different way. It does not show that semantic guards are useless; it shows that our sandbox could not exercise them.

\subsection{Applying the Discipline to an Existing Guardrail Design}

To illustrate how \tint{} applies beyond DevAgent, consider a hypothetical coding-agent deployment that combines three published components of LlamaFirewall as their authors describe them~\cite{arxiv250503574}: an input classifier for jailbreaks and injections, an LLM-based alignment check that audits the agent's reasoning for goal hijacking, and a static analyzer for generated code. Writing the edges down raises three questions that the components' own evaluations do not answer. First, the alignment check reads the agent's reasoning, which may quote attacker-authored tool output; its obligation ``my input contains no instructions addressed to me'' is therefore assumed rather than established, which is the situation of Proposition~\ref{prop:t0}, unless the deployment passes it a projection in the sense of the previous subsection. Second, none of the three components decides $\varphi_2$; information-flow control needs a deterministic gate over provenance labels, which the host must add. Third, if the classifier's verdict may accept an action without consulting the alignment check, the pipeline is an early-accept cascade, and its risk is the sum over the classifier route and the alignment-check route, not a product of their miss rates. The exercise needs no API access and produces, per deployment, a list of assumed obligations that a team can then decide to check, establish by construction, or accept. We have not validated such a mapping with practitioners.

\subsection{What a Convincing Evaluation Needs}

To move from feasibility to effectiveness, an evaluation needs real coding agents on realistic tasks~\cite{jimenez2023swebench}, learned guards and LLM judges~\cite{arxiv231206674,arxiv250503574}, independently annotated semantic labels, and an attacker who adapts to the guards' responses~\cite{arxiv230715043,arxiv250411168}. Within a scripted sandbox, three changes would already make the semantic trade-off observable: benign issue-derived actions that a judge can recognize as benign, so that provenance alone cannot separate safe from unsafe; a raw-text judge that genuinely benefits from text, so that the structured view has a measurable utility cost; and several paraphrases per family, so that selection is not degenerate. Matched comparisons against provenance-based isolation~\cite{arxiv250318813} and runtime rule enforcement~\cite{arxiv250318666} complete the list. The runtime accepts callable scorer and judge interfaces so that such components can be plugged in, but providing adapters is not evidence that the discipline works with real models.

\section{Threats to Validity}
\label{sec:threats}
% =====================================================================

We follow the usual classification~\cite{wohlin2012experimentation}.

\textbf{Internal validity.} We authored the fixture law, the guards and the comparators, and the templates were committed after the preregistration tag, with knowledge of the scorer. The comparison outcomes are therefore consequences of our design, which we report as such. We mitigated designer bias by freezing thresholds, budgets and analyses before any run, by including a strong control that keeps the gate, by reporting a post hoc comparator that beats our method, and by publishing every decision. The primary instrument contained a numeric defect; we preserved its results, fixed only the arithmetic and evaluated the fix on fresh seeds. The adaptive-search instrument queried the uncertified decision core and never adapted, and we report it as uninformative. Calibration losses were computed by a decision core separate from the runtime; replay found no disagreement, but the two do not share code.

\textbf{Construct validity.} Joint unsafe acceptance is a per-decision measure, not the probability that a session causes harm, and benign utility counts accepted benign proposals without asking whether a task succeeds. Modeled costs encode an intended ratio, not time or money, and our wall-clock times measure Python bookkeeping. The structured-view judge is a deterministic surrogate, and the design cannot observe what a structured view costs a real judge in lost semantics.

\textbf{External validity.} No real LLM, learned guard, external benchmark or human participant was involved, and the sandbox interprets typed actions in memory. Seven families with one template each, whose only benign issue-derived family is blocked by the judge, cannot represent real issues and attacks. The runtime supports a single topology. The results do not transfer to deployed agents without new evidence.

\textbf{Conclusion validity.} Decisions are deterministic per family, so the paired tests can only confirm sign consistency, and their $p$-values sit at the floor for ten seeds; intervals reflect sampling of family proportions. The coverage experiment has a Monte Carlo standard error of about $0.007$ at $0.95$ coverage with a thousand replications, small relative to the observed margin.

\section{Related Work}
\label{sec:related}
% =====================================================================

\textbf{Trust and composition.} That trust is not transitive is a classic observation in security protocols~\cite{christianson1997why}. Assume-guarantee reasoning~\cite{misra1981proofs,jones1983tentative,abadi1993composing} and contract-based design~\cite{benveniste2018contracts,meyer1992applying} make it precise for component composition, and probabilistic and stochastic contracts give composition rules for probabilistic guarantees~\cite{delahaye2011probabilistic,nuzzo2019stochastic}. Our contracts are a lightweight instance of these theories; we do not develop a contract algebra, and instantiating Definition~\ref{def:contract} in a stochastic contract framework could yield composition rules beyond Lemma~\ref{lem:edges}. Our contribution is operational: obligations typed by how they are established, a checker and runtime for guardrail hierarchies, and certificate applicability as a checked obligation.

\textbf{Guard models and guardrail frameworks.} Classifier guards screen prompts and responses~\cite{arxiv231206674,arxiv240618495}, and constitutional classifiers defend against universal jailbreaks~\cite{arxiv250118837}. Activation probes monitor model internals~\cite{arxiv250926238}, though obfuscated activations can evade them~\cite{arxiv241209565}. Reasoning guards deliberate before deciding~\cite{arxiv250213458}. Frameworks combine several guards with programmable rails~\cite{arxiv231010501,arxiv250721170}, and LlamaFirewall layers injection detection, alignment checks and code scanning for agents~\cite{arxiv250503574}. Evasion studies show that guards can be bypassed~\cite{arxiv250411168,arxiv250305264,arxiv230715043} and that their behavior changes with retrieved context~\cite{arxiv251005310}. These works motivate hierarchies; \tint{} asks what a hierarchy guarantees and when.

\textbf{Runtime enforcement for agents.} AgentSpec specifies triggers, predicates and enforcement actions for agent runtime rules~\cite{arxiv250318666}, and ProbGuard predicts unsafe states probabilistically~\cite{arxiv250800500}. ShieldAgent verifies actions against policies extracted from documents~\cite{arxiv250322738}, VeriGuard generates verified policy code~\cite{arxiv251005156}, and agent behavioral contracts and NaSh specify and enforce agent behavior~\cite{arxiv260222302,arxiv250613028}. Task alignment checks~\cite{arxiv241216682} and guardrails for LLM-controlled robots~\cite{arxiv250307885,arxiv251221220} apply similar ideas in other domains. ContrAgent specifies agents with assume-guarantee temporal contracts and compiles them into deterministic monitors~\cite{arxiv260918128}. Our DSL is much smaller than these languages; \tint{} adds the treatment of statistical guards as contract-bearing layers whose edges and certificates are checked. Edit automata and related theory characterize what runtime monitors can enforce~\cite{schneider2000enforceable,ligatti2005edit}, and runtime verification~\cite{leucker2009brief} and the Simplex architecture~\cite{sha2001using} supply the monitor-first design.

\textbf{Provenance and isolation.} CaMeL separates control and data flow so that untrusted data cannot change the program an agent executes~\cite{arxiv250318813}, Fides applies information-flow control to agent planning~\cite{arxiv250523643}, and the dual-LLM pattern separates a privileged planner from a quarantined reader~\cite{willison2023dual}. Spotlighting marks untrusted input in the prompt~\cite{arxiv240314720}, and instruction hierarchies train models to prioritize privileged instructions~\cite{arxiv240413208}. These techniques implement classical reference-monitor and information-flow principles~\cite{anderson1972computer,saltzer1975protection,denning1976lattice,sabelfeld2003language}. \tint{}'s gate and structured view are instances of the same principles, and our post hoc comparator B7 suggests that, where provenance suffices, these systems' data-flow guarantees are the stronger tool.

\textbf{Cascades and statistical guarantees.} Model cascades trade cost and quality~\cite{arxiv230505176}. Conformal Arbitrage calibrates routing between a primary model and a guardian~\cite{arxiv250600911}; Trust or Escalate gives provable human-agreement guarantees for cascaded judges~\cite{arxiv240718370}; hybrid and conformal abstention control reliability~\cite{arxiv260215391,arxiv240501563}. Conformal methods also control tail risk, factuality and set coverage for LLMs~\cite{arxiv250220285,arxiv240210978,arxiv230610193,arxiv230518404,arxiv240301216,arxiv240617819}, and conformal prediction supports runtime verification of temporal properties~\cite{lindemann2023conformal}. Shielding enforces safety of reactive and learning systems at runtime~\cite{arxiv150102573,arxiv170808611,arxiv190805402,arxiv240604184}, and ScenicProver composes probabilistic evidence for learning-enabled systems~\cite{arxiv251102164}. A position paper argues for a layered probabilistic assume-guarantee architecture for agents~\cite{arxiv260518672}. These methods supply the guarantees that \tint{} binds to configurations; \tint{}'s concern is to check, at the edge where a verdict is used, that the input view and configuration are those the guarantee was about, and to list the distributional assumption that cannot be checked.

\textbf{Benchmarks.} AgentDojo, ASB, AgentHarm, ToolEmu, R-Judge, RedCode and others measure attack success and defense utility for agents~\cite{arxiv240613352,arxiv241002644,arxiv241009024,arxiv230915817,arxiv240110019,arxiv241107781,arxiv251002609,arxiv240801605,arxiv250816481}; a recent study cautions that benchmark representations can change measured threat~\cite{arxiv261003585}. A real-agent evaluation of \tint{} should use them.

\section{Conclusion}
\label{sec:conclusion}
% =====================================================================

Guardrail hierarchies for LLM agents are built from guards whose guarantees are conditional, and those conditions do not travel along the chain of trust by themselves. \tint{} makes them explicit: trust edges carry named obligations, each established by a runtime check, by construction, or listed as an assumption; a deterministic gate that no semantic layer can bypass enforces information-flow and approval policies; the judge sees a structured view; and certificates apply only to the configuration they were computed for. Under five stated premises such a composition bounds end-to-end risk by a sum over acceptance routes, and a cost-minimal certified policy can be selected exactly within a finite family. A protocol-registered study in a scripted sandbox showed that the discipline is implementable and that each mechanism behaves as designed, including refusing service when a defective scorer made certification impossible. It also showed the limits plainly: a simple provenance rule did better in our sandbox, certification changed no decision once the defect was fixed, and no semantic mechanism resisted a shift that the one assumed obligation predicted. Whether the discipline makes real LLM agents safer at acceptable cost requires real agents, learned guards, benign issue-derived work that a judge can recognize, and adaptive attackers to answer.
