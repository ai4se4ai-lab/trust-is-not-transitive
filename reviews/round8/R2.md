## 2. Findings, by severity

### Critical

**1. The assumption list misses needed assumptions.**
Location: `src/tint/hsl/__init__.py:362-364`; `necessary` at `:429`; `main.tex:581` ("shows which claims an assurance argument rests on, and which of them are needed"), `:799-803`, `:1271`, `:1356`.
Problem: `relevant` for a gate is true only if `establishes` is an open goal. So a veto stage's assumed evidence is dropped from `residual` when the stage's value is the fact it provides, or when its goal is already established but its fact is still needed. Because `necessary` only filters `residual`, it cannot recover the entry.
Reproduction: veto gate `v` with layer `V` (requires `x`), evidence `{x}`, establishes nothing, provides `o`; then guard `n` requiring `o` with scope `{g}`.
- `check` gives ok, `residual=()`, `necessary=()`.
- Removing `x` gives a rejection: `obligation n o`.
So the tool reports nothing assumed while the safety of the hierarchy rests on an assumption. This breaks the stated definition of the residual ("supplied at a stage that some goal depends on"). Corollary 1 is untouched, but it covers only what the list contains. The paper now names this list as the main result for real stacks. None of E3-E6 compares the list with anything, and no test fails. The E13 designs escape only because none has a fact-providing veto stage.
Fix: define the residual as every supplied assumed obligation at any stage, and let `necessary` do the filtering. Or compute relevance from goals and facts backward. Then add an oracle: for random accepted specs, an entry is reported necessary iff removing it causes rejection, over all assumed evidence and not just the listed entries. Add this to E4.

### Major

**2. Stale certificates can still stay open. Two siblings of round 7 finding 5.**
Location: `engine.py:99-100, 38-53`; `main.tex:990`.
Problem:
- A gate's `own` tuple omits its layer's `view`, `requires` and `scope`, though the guard tuple includes them, and `_run:217` uses the view to decide what the rule sees. I changed a veto stage's layer from `raw` to `metadata`: identical fingerprints, `affected_routes` empty, opposite decisions on the same proposal, and the old certificate opened on the changed engine and accepted. This is an ordinary configuration edit and contradicts "a change to a stage" staling its routes.
- `_value_digest` falls back to `repr`, and repr need not cover state. An `ndarray` of 5000 entries differing in the middle gave equal digests (numpy truncates), as did a nested object with a custom `__repr__`, which is what fitted estimators have. The paper says identity covers "instance state". The disclosure of "files such as model weights" does not cover weights held in memory on the instance, and that is the common case for a retrained scorer, the very case of the introduction.
The four `gap` survivors of E5 sit exactly here and were judged harmless.
Fix: hash the whole gate layer. Remove the `repr` fallback for anything but primitives: hash arrays by bytes, and refuse unknown types. Add both cases as tests. Reword "instance state".

**3. E12b does not test what the paper says, and its restriction is undisclosed.**
Location: `run.py:806-808, 815-816`; `main.tex:1211` ("compares deployed risk with the sum of open bounds"), table `tab:exps` row E12b, table `tab:mapping`; `PROTOCOL.md` Amendment A (mentions the restriction only for E11).
The theorem has two parts: R is the sum over Q (hard routes carry zero), and the sum is bounded. E12b's treatment:
- **Restriction.** `true_risk = risk(altered, variant, set(needing))` drops hard routes, with a comment citing premise (i). Excluding them would be fair if premise (i) held in the law. It does not. `unsafe` is an independent coin (`rng.random()<.3`) with no relation to any goal, and gates are scripted coins. So premise (i) is false by construction wherever it matters, the excluded mass is real in the law, and what is compared is not deployed risk.
- **Magnitude**, from my replay of the 48 seeds. 5 of the 42 retained laws have positive hard-route unsafe mass, up to 0.057. In one law it is 0.057 against 0.027 on the statistical route, whose mean bound is 0.044, so that law would fail outright if measured as described. The 6 discarded laws (`if not needing: return None`) are all-hard DAGs with unsafe accepted mass up to 0.095 and no bound at all.
- **Consequence.** The step "hard routes contribute zero", and the need for premises (i) and (ii), are assumed and never exercised. No part of the test depends on the check: `report.ok` is a filter only, and `needs_certificate` could be wrong without any effect. With `statistical = all goals`, G_d is empty, so premise (ii) is empty too. What is tested is CP plus a union bound on a DAG. E12 did that already, with partial reuse added.
- **No deployed decision.** `rebuilt` (line 815) is constructed and never used. Risk uses `shadow`, and `evaluate` is never called. Kept certificates have their fingerprint **overwritten** with the variant's value, so the only step that could expose a fingerprint error is disabled. There is no assertion that all routes opened.
- **Weak read of the sum.** Sum coverage is 1.000 on most laws, so the test has little power for the multi-route sum; the single-route laws set the minimum. Median statistical routes per law is 2.
- **Record.** E12b's result was saved at 17:02, right after `run.py` was saved at 17:01. If an earlier version measured all routes and failed, the protocol requires that first result in the errata, and it is absent. If not, say so. The Wilson `z=3.09` is hard-coded and does not derive from the number of laws, which was 42 after discards.
Fix: generate laws that satisfy the premises. Draw per-goal violations; make each deterministic gate pass exactly when its goal holds, and draw guards freely. Let G_d be non-empty, and give gates contracts that hold. Measure R over all routes, keep the all-hard laws, and assert R on hard routes is 0. Add a negative control with an inexact gate, which should fail. Compute risk through `Engine.evaluate` on `rebuilt`, assert open routes, and do not rewrite fingerprints. State in the paper that the current law violates premise (i), or replace it.

**4. E15's denominators, tally and generalization.**
Location: `corpus_analysis.py`; `experiments/v2/corpus/nemo_rails.json`; `main.tex:581, 1271, 1356`.
- **Silent exclusion.** 72 of 139 configurations are Colang 2.x, and **none** has a rail extracted, because Colang 2 declares rails in `.co` files, outside the `rails` section of the YAML. 92 of 139 contribute nothing. "43 of 139" reads as a prevalence, but the reachable population is the Colang 1 configurations, and the exclusion appears nowhere.
- **Code contradicts text.** Line 1271 says "with no bound supplied, 39 of 43 leave a goal open". The code *supplies* the bound (`Gate(..., frozenset({BOUND}))`) and withholds `contract_holds_on_adversarial_text`. The field is called `open_under_adversary`. The number happens to be the same either way, which is the next point.
- **Tautology.** One invented goal per rail makes each rail its goal's only cover, so a configuration is "open" iff it has any non-deterministic, non-transforming rail: 43 minus 1 deterministic minus 3 mask-only. No analysis happens. The goal-per-rail choice is a modelling decision, though the docstring says the encoding is "not a modelling choice of ours". The 3 mask-only configurations count as closed although the paper says rewriting cannot be expressed.
- **Unmeasured fields.** `'escalating': 0` is a literal, the same defect as round 7 finding 1. `parallel` can only be 0, because the corpus keeps no `.parallel` key, and `tools` is False on all 139 rows. NeMo documents a parallel option for rails, so "run in sequence" should be checked. The paper's "None escalates" is an argument about the framework, not a result, and should be phrased so.
- **Classification.** The default bucket is `model_or_service`, by name, by one rater, with no reliability figure. `jailbreak detection heuristics` is encoded as a deterministic gate, which decides its goal exactly in the calculus, although it is a thresholded heuristic. That contradicts the paper's rule at line 1023 that a stage is a deterministic gate only if it decides the goal exactly. It does not change the count.
- **Generalization.** Most of the 43 are one-vendor integration demos (input plus output rail), and 6 have the same rails as one content-safety example. The maximum of 9 is `examples/sample_config.yml`, a documentation sample containing "some other moderation thing". Shortness may be a property of demos. The body hedges well, yet the abstract says "today's stacks are short chains of statistical stages", and the conclusion says the same.
- **Provenance.** No extraction script exists in the artifact, so the JSON cannot be regenerated or audited.
Fix: publish the extractor. Parse `.co` files, or state the exclusion and report over Colang 1 only. Deduplicate and report distinct shapes. Remove the `escalating` and `parallel` fields or measure them. Have a second rater. Drop the 39-of-43 sentence, or say that it counts configurations with a statistical rail. Rewrite the abstract as "examples in one framework's repository". Reviewing a handful of production configurations would help far more than more counts.

**5. E13's rule is less mechanical than claimed, and DevAgent's adversarial pass rests on an unlisted choice.**
Location: `run.py:849-855`; `cases/*.json`; `main.tex:934, 1025, 1289`, table `tab:cases`.
Problem: `adversarial()` is mechanical given two hand labels: which stages are `raw` and which are learned. `miss_rate_bounded` is written by hand.
- DevAgent's human `L4` is `structured`, so the rule skips it. Setting it to `raw` makes DevAgent **rejected** at `n4` under the adversarial model. Yet line 934 says a stage reading the structured view cannot decide phi3 on a patch, "a guard that must judge content has to read it, and then it can be addressed by it", and the Worked Example has the person judging the patch on T_j' ("depends on the person"). The person's exposure is absent from the table's "rests on" column. `policy_inventory`'s judge has the same mismatch: scope `semantic_injection` on a `structured` view.
- CaMeL's planner is an LLM with no `miss_rate_bounded`. Applying "every learned stage requires" literally gives **rejected**. The exemption may be right, since its guarantee is not statistical, but it is a judgement, and line 1025 says verdicts do not depend on such feeling.
- DevAgent receives the bound though "supplied only if the source states a bound" has no source here, and the paper's own earlier study refused certification in all primary seeds.
- `repair` returns a sufficient set, not a minimal one, and the column heading does not claim otherwise. That is fine.
Fix: state the labels as inputs of the rule, justify each with a quotation, and report these two flips in the sensitivity column of `tab:cases`. Add `human_reads_attacker_text_safely`, or similar, to the human contract. Reconcile line 934 with `L4`.

**6. E4's "power" and denominator are weaker than the sentence suggests.**
Location: `harness.py:195-208`; `main.tex:1218`.
Problem: on 1,500 specs from the E4 stream:
- Of contract-respecting runs on accepted specs, only 12% end in acceptance (956 of 8,058), so 217,255 corresponds to about 26,000 informative runs. 24% of accepted specs have no route, so they cannot fail at all.
- "So it has the power to find them" is a pooled count. Only 51% of rejected specs (419 of 829) had any unsafe run in 20 samples. An unsound acceptance on a hard-to-hit path would pass half the time per spec.
The theorem and model search carry the real weight, so this does not threaten the result. The sentence overstates it.
Fix: report accepted-run denominators, exclude route-less specs, report per-spec sensitivity, and bias sampling toward acceptance (guards accept, obligations hold except one).

**7. E5: some "equivalent" labels are false, and the classifier cannot do what its docstring says.**
Location: `classify_mutants.py`; `mutation.py:20-22`; `main.tex:1220`; Amendment A.
I read all 33 survivors.
- `__init__.py:321` (`known | gained` to `&`) and `:319` are labelled equivalent because "exact exploration repairs" them. The verdict is repaired, the report is not. For gate `p` providing `o`, veto `v` requiring `o` and establishing `g`, and guard `n` with assumed evidence `x`: the original gives `residual=()`, and the mutant at 321 gives `residual=(('n','x'),)`. The class definition says "no verdict, decision or fingerprint distinction", which leaves the residual out, and that is the very output the paper highlights. Reclassify these as gaps. They also show that no oracle examines the residual, which is how finding 1 survived.
- The rule `('__init__.py', '', 'const', ...)` matches any surviving constant mutant in that file, and `(... '| None' ...)` any annotation. So "a survivor without a rule stops the script, so a new survivor cannot go unread" is false for this class. A new survivor there gets labelled equivalent unseen. The four present ones are indeed fine (lines 402, 406, 432, 436; 406 shifts the state count that is reported in E9).
- My checks of the rest agree: `x | -x` has the same `bit_length`, the edge-label mutants are bijective, the entry flag is redundant.
- 14 survivors are annotations, which are not behaviours. They should not be mutation sites, as they sit in the denominator.
- Amendment A says targets include "parsing helpers". `TARGETS` has no `parse`, `_keys`, `_names`, `_ref` or `_unique`. `Gt` and `Lt` have no swap, and only `ops[0]` is mutated, so `> budget`, `> delta`, `0 < self.delta < 1` get no boundary mutants.

- `test_hsl_oracle.py` was last saved at 17:18, about a quarter-hour before the final result. The paper says tests followed "an earlier run on a smaller set of functions". If survivors of the extended set also informed tests, say so. There is still no held-out set.

**8. E3's four-node model search is an aliased sample: every sampled hierarchy has one goal.**
Location: `run.py:45-47`; `harness.py:166-184`; `main.tex:1216`.
Problem: `enumerate_small` yields each structure twice, goals `{a}` first and `{a,b}` second, and `e3_worker` selects `count % 64 == 0`. Since `count` is always even at that point, **no** two-goal hierarchy is ever selected. I replayed 65 of the 156 partitions: 30,447 sampled, all `|goals| = 1`, against a 50/50 population; the code path makes this hold for all. The stride also aliases with the 36 options of the last node (in my replay, 8 (type, layer) kinds at the last node, with no veto stage and no switch there). So "every 64th of four nodes" is literally true, but the sample has no multi-goal 4-node case, and the paper's alphabet sentence implies otherwise. The zero disagreements stand, and E4's small search and my round 7 probe partly cover the gap, so I treat this as major, not critical.
Separately, no veto gate in E3 provides a fact (`small_options` gives `provides` only to deterministic gates, and only `{o}`). So conditional provision, the source of hardness in Theorem `thm:complexity`, is outside the exhaustive bound. E4, E7 and E14 cover it. The paper's "gates with and without facts" hides this.
Fix: select by a hash of the spec or by a seeded Bernoulli, and report the composition. Add veto gates with facts to the alphabet. Then a small-scope argument would have real force.

## Summary for the editor

The revision answers most of the first report, and with real instruments rather than rewording. What remains is specific. The checker can report an empty assumption list for a hierarchy that depends on an assumption, which undercuts the paper's stated main value (finding 1). Fingerprints still miss a veto stage's view and in-memory weights (finding 2). E12b excludes unsafe mass from "deployed risk" without saying so, in laws that violate the theorem's premise, so the Route risk theorem remains untested (finding 3). E15 silently loses 72 Colang 2 configurations and its key sentence does not match the code (finding 4). I would ask for findings 1-8, a tagged rerun, and a short re-review.
