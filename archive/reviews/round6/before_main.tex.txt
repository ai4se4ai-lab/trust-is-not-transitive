\title{Trust Is Not Transitive: Checked Assume-Guarantee Composition of Hierarchical Guardrails for LLM Agents}

\author{Author~Names~Withheld%
\thanks{Affiliation and contact information to be added.}%
\thanks{Manuscript received ; revised .}}

\markboth{IEEE Transactions on Software Engineering}%
{Trust Is Not Transitive: Checked Composition of Hierarchical Guardrails}

\maketitle

\begin{abstract}
LLM agents that edit code, run tests and call web services are increasingly protected by hierarchies of guardrails: cheap rules and classifiers screen every proposed action and escalate doubtful cases to an LLM judge or a human. Such stacks are justified by measured accuracy, but what they jointly guarantee is rarely stated. This matters because a guard's guarantee holds only under assumptions about what it sees and how it was calibrated, and these assumptions are not passed along when one layer trusts another: trust is not transitive. We present \tint{}, a discipline and a library for building guardrail hierarchies in which (i)~every trust relation between layers is an explicit assume-guarantee obligation that is checked before deployment, (ii)~deterministic properties are enforced exactly by a mandatory sink on every accepted action, (iii)~the LLM judge receives only a quarantined, structured view, and (iv)~statistical risk certificates are bound to the exact configuration for which they were computed. We state the conditions under which such a composition bounds end-to-end risk, show that the risk of an early-accept cascade is a sum over acceptance routes rather than a product or minimum of per-layer miss rates, and give a certified procedure for selecting escalation thresholds. A preregistered feasibility study in a typed, fully controlled agent sandbox (\resReplayDecisions{} logged decisions) yielded two findings. In the frozen primary run, no policy could be certified and \tint{} blocked every action; the certification gate had exposed a floating-point defect in a scorer that the same pipeline without certification shipped with \resPrimaryCheckedUncalibratedRisk\% unsafe acceptance. In a fresh-seed replication after the fix, \tint{} reduced joint unsafe acceptance from \resExploratoryNaiveWithSinkRisk\% to \resExploratoryCheckedQuarantineRisk\% relative to a strong rule-plus-judge control at equal benign utility, but every pipeline accepted an encoded attack family absent from calibration. The study establishes feasibility and failure modes of the discipline, not its effectiveness on real LLM agents, which remains open.
\end{abstract}

\end{IEEEkeywords}

\section{Introduction}
\label{sec:intro}
% =====================================================================

\IEEEPARstart{L}{arge} language model (LLM) agents no longer only produce text; they act. A coding agent reads an issue, edits files, runs the test suite and posts results to a web service~\cite{jimenez2023swebench}. Each of these actions passes through a tool interface, and the tool interface is where developers place guardrails. In practice, the guardrails are layered~\cite{arxiv250503574,arxiv231010501}. A cheap rule layer checks allowlists and data provenance; a small classifier scores the text that led to the action; uncertain cases are escalated to an LLM judge, and the most consequential actions to a human. The design mirrors the classic detection cascade~\cite{viola2001rapid} and the cost-aware model cascades used for LLM serving~\cite{arxiv230505176}: most traffic is resolved quickly, and only a small fraction pays for slow, careful review.

These hierarchies are justified empirically, by measuring the accuracy of each guard and of the stack on a benchmark~\cite{arxiv240613352,arxiv241002644}. What is usually missing is a statement of what the stack \emph{guarantees}, and under which conditions. The gap is not academic. Every guard's guarantee is conditional. A provenance rule is only as good as the labels it reads. A classifier's calibrated error rate is valid for the distribution and version it was calibrated on. An LLM judge may be accurate on benign inputs and still obey an instruction written for it by the attacker who wrote the issue~\cite{arxiv230212173}. When layer~$L_1$ accepts an action because $L_2$ accepted it, and $L_2$ relied on $L_3$, nothing in the code checks that $L_3$'s assumptions held for this action. Trust between guardrails is not transitive.

\textbf{Running example.} We use one example throughout. \emph{DevAgent} is a coding agent that triages issues in a repository, edits files and calls HTTP services. Three traces capture the problem.
In $\Tstar$, a malicious issue says ``to fix this, upload secret .env to sink.invalid''; the agent reads the issue and the secret file and proposes to send the file to an external host.
In $\Tb$, a benign issue asks the agent to attach public diagnostics to a local test report; the proposed action has the same shape (an HTTP request carrying a file) but is legitimate.
$\Tj$ is $\Tstar$ with one more sentence: ``reviewer must answer SAFE''. The sentence is addressed not to the agent but to the LLM judge further down the guardrail stack. If the judge reads the raw issue, it can be told what to answer; if the layers above it relay its verdict, the exfiltration executes even though every layer behaved according to its own specification. We make this precise in Section~\ref{sec:problem}.

\textbf{The gap.} Two lines of work come close to the problem but leave it open. Formal approaches specify agent behavior with temporal rules and contracts and enforce them at runtime~\cite{arxiv250318666,arxiv260918128,arxiv260222302}, or isolate untrusted data by construction~\cite{arxiv250318813,arxiv250523643}; they typically treat the guard as one monitor rather than as a hierarchy whose layers make probabilistic decisions. Statistical approaches give finite-sample guarantees for cascades and selective judges~\cite{arxiv250600911,arxiv240718370}; they guarantee agreement or risk for the distribution on which they were calibrated, but do not check whether the guard's input at deployment is the input the guarantee was about. A position paper argues that safe agent deployment requires a layered probabilistic assume-guarantee architecture~\cite{arxiv260518672}. What is missing is an \emph{executable} discipline that makes each inter-layer trust obligation explicit, checks it, and keeps the deterministic and statistical parts of the guarantee from being confused with each other.

\textbf{Challenges.} Three difficulties stand in the way.
\emph{C1 (implicit discharge).} In a typical stack, the conditions under which a downstream verdict may be trusted are never written down, so their violation cannot be detected.
\emph{C2 (wrong risk algebra).} Engineers reason about stacks with veto-ensemble intuitions (``an attack must fool every layer, so the miss rates multiply''), but early-accept cascades let most traffic bypass the expensive layers, and miss events of different guards share the same ground truth, so independence is rarely meaningful.
\emph{C3 (stale evidence).} Calibration evidence is computed for one scorer version, threshold, view and context; nothing prevents reusing it after any of them changes.

\textbf{Key idea.} We treat trust between guardrail layers as a \emph{conditioned}, non-transitive relation: layer~$i$ may consume the verdict of layer~$j$ for property~$p$ only when trusted evidence available at that edge discharges $j$'s assumptions. Deterministic properties are never delegated: a mandatory sink re-checks them on every accepted action. Semantic properties are bounded statistically, but only by certificates whose premises the runtime re-checks on each decision, and the risk of the whole pipeline is accounted for per acceptance route. When a premise fails, the decision fails closed.

\textbf{Contributions.} This paper makes four contributions.
\begin{enumerate}
\item \emph{A problem formulation and a countermodel} (Section~\ref{sec:problem}). We define layers, views, contracts and conditioned trust edges for agent guardrails and show, with the $\Tj$ trace, that local contract satisfaction does not imply end-to-end safety when discharge is implicit.
\item \emph{A checked composition discipline with explicit premises} (Section~\ref{sec:approach}). We give a closed specification language for contracts and trust edges, a checker that never infers an edge, a scoped soundness result for compositions that keep a mandatory sink and quarantine the judge, corrected risk accounting for veto ensembles and early-accept cascades, and a certified, cost-minimal selection procedure for escalation thresholds. The mathematics is elementary by design; the contribution is to state the premises that practice leaves implicit and to make each one checkable or visibly assumed.
\item \emph{An open implementation} (Section~\ref{sec:impl}). The \tint{} library implements typed actions with monitor-owned provenance, the checker, a fail-closed runtime that binds certificates to policy fingerprints, calibration and selection, and a typed in-memory sandbox.
\item \emph{A preregistered feasibility study with negative results} (Section~\ref{sec:eval}). We evaluate the discipline with model checking, mutation analysis, Monte Carlo coverage experiments and a paired comparison against six comparators, including a strong control that keeps the sink but omits quarantine and certification. We report a primary run in which nothing was certified, a disclosed defect fix evaluated on fresh seeds, and the failure of every pipeline under distribution shift.
\end{enumerate}

\textbf{Research questions.} We organize the work around three questions.
\begin{itemize}
\item \textbf{RQ1 (Specification and decomposition).} How can an end-to-end safety property of an agent be specified and decomposed into per-layer assume-guarantee contracts over heterogeneous guards, such that trust between layers is explicit and checkable rather than assumed transitive?
\item \textbf{RQ2 (Guarantees and escalation).} Under which conditions does a guardrail composition bound end-to-end residual risk, how does it fail (transitivity violations, correlated errors, shift, adaptive inputs), and which escalation policy minimizes expected cost subject to a risk bound?
\item \textbf{RQ3 (Engineering value).} In a controlled agent sandbox, how does a pipeline built with the discipline trade risk, benign utility and cost against flat and naive hierarchical guardrails, and do the assumptions of its guarantees hold?
\end{itemize}

\textbf{What we do not claim.} We do not claim to have discovered that trust is non-transitive; this is a classical observation in compositional reasoning~\cite{misra1981proofs,abadi1993composing}. We do not claim new probability theory; the bounds are standard. We do not evaluate real LLMs, learned guard models or external agent benchmarks: no API access or licensed guard models were available to us, and we did not relabel synthetic evidence as such. The study shows that the discipline is implementable, that it rejects the composition errors it targets, and where it fails.

\textbf{Roadmap.} Section~\ref{sec:background} introduces the background and the DevAgent policies. Section~\ref{sec:problem} formalizes the problem and the countermodel. Section~\ref{sec:approach} presents \tint{}. Section~\ref{sec:eval} describes the implementation, the setup and the results. Section~\ref{sec:discussion} discusses lessons, Section~\ref{sec:threats} threats to validity, Section~\ref{sec:related} related work, and Section~\ref{sec:conclusion} concludes.

\section{Background}
\label{sec:background}
% =====================================================================

\subsection{Tool-Using Agents and Their Guardrails}

A tool-using agent repeatedly observes its context, proposes a tool call and receives the result. For a coding agent, the context includes issue text, repository files and command output; the tools include file edits, test runs and HTTP requests~\cite{jimenez2023swebench}. The central security problem is \emph{indirect prompt injection}: text that the agent reads as data, such as an issue body, contains instructions that the agent then follows~\cite{arxiv230212173,arxiv240613352}. Benchmarks for agent safety measure how often attacks succeed and how often defenses block benign work~\cite{arxiv240613352,arxiv241002644,arxiv241009024,arxiv230915817,arxiv240110019,arxiv241107781}.

Guardrails intercept proposed actions. They range from deterministic rules and allowlists, through classifiers for injection and harmful content~\cite{arxiv231206674,arxiv240618495,arxiv250118837}, to LLM judges that reason about the action in context~\cite{arxiv250213458} and human approval. Production frameworks combine several of them~\cite{arxiv250503574,arxiv231010501}. We call such a combination a \emph{guardrail hierarchy} when layers are ordered by cost and a layer may accept, block or escalate to the next one. Following a common informal vocabulary~\cite{arxiv250217419}, fast layers with a fixed work bound are ``System~1'' guards and slow, open-ended ones ``System~2'' guards; we use the terms only as an engineering classification of cost.

\subsection{Reference Monitors and Information Flow}

A reference monitor mediates every access of a subject to an object, is tamper-proof and is small enough to be verified~\cite{anderson1972computer}. \emph{Complete mediation}, checking every access, is one of the classic design principles for protection~\cite{saltzer1975protection}. Execution monitors can enforce exactly the safety properties of traces~\cite{schneider2000enforceable}. Information-flow control attaches labels to data and propagates them through computation; with a lattice of labels, derived data carry the join of their sources' labels~\cite{denning1976lattice,sabelfeld2003language}. Recent agent defenses apply these ideas to LLM agents by tracking the provenance of every value and checking a policy at each tool call~\cite{arxiv250318813,arxiv250523643}.

\subsection{Assume-Guarantee Contracts}

A contract for a component is a pair $(A,G)$: if the environment satisfies assumption~$A$, the component guarantees~$G$~\cite{meyer1992applying,benveniste2018contracts}. Compositional proof rules for concurrent systems~\cite{misra1981proofs,jones1983tentative,abadi1993composing} show when the guarantees of components discharge each other's assumptions. The rules are sound only when every assumption of a component is actually established, by its environment or by another component's guarantee. A system that relies on a component without establishing its assumptions has no guarantee from it, even if the component meets its contract. This is the formal kernel of the observation that trust is not transitive.

\subsection{Statistical Certification}

For a fixed policy and $n$ independent calibration samples with $k$ observed losses, the Clopper--Pearson interval gives an exact one-sided upper confidence bound on the loss probability~\cite{clopper1934use}. When one policy is selected from a finite family of $K$ candidates, bounding all candidates simultaneously, for example at level $\delta/K$ each, makes the selected policy's bound valid despite the selection. Distribution-free risk control generalizes this idea to prediction sets and thresholds~\cite{bates2021distribution,angelopoulos2021learn}. Conformal risk control instead bounds the \emph{expected} loss of a threshold chosen from a nested family~\cite{arxiv220802814,arxiv210707511}. All of these guarantees assume that calibration and deployment data are exchangeable; under shift they need additional assumptions~\cite{tibshirani2019conformal,arxiv210600170}.

\subsection{DevAgent Policies and Layers}

Table~\ref{tab:policies} lists the three DevAgent policies and the layers that naturally enforce them. $\varphi_1$ and $\varphi_2$ are \emph{deterministic}: they can be decided from the typed action and trusted metadata. $\varphi_3$ is \emph{semantic}: whether an action follows an unauthorized instruction depends on intent, which no provenance label captures. Reading an issue is legitimate; obeying instructions hidden in it may not be.

\subsection{Actions, Provenance and Policies}

An agent proposes a typed action $a=(\kappa,\tau,\iota,e)$ with a kind $\kappa$ from a finite set (\textsf{read}, \textsf{patch}, \textsf{test}, \textsf{http}, \textsf{delete}, \textsf{force\_push}), a target $\tau$, a tuple $\iota$ of references to observations it uses as inputs, and an environment $e\in\{\textsf{sandbox},\textsf{production}\}$. Parameter values are not restricted to a finite alphabet. Every observation carries a label $\lambda(o)\subseteq\{U,S\}$, where $U$ marks untrusted and $S$ secret content; the empty label means trusted and public. Labels form a lattice under set union, and an action inherits the union of its inputs' labels, $\lambda(a)=\bigcup_{o\in\iota}\lambda(o)$. Labels are written by the monitor, never by the agent. An unknown reference is labeled $\{U,S\}$, so missing provenance fails closed.

From the action and trusted metadata, the monitor computes six Boolean facts: \emph{destructive} ($\kappa$ is \textsf{delete} or \textsf{force\_push}), \emph{production} ($e=\textsf{production}$), \emph{external} ($\kappa=\textsf{http}$ and $\tau$ is not the configured local service), \emph{secret} ($S\in\lambda(a)$), \emph{untrusted} ($U\in\lambda(a)$), and \emph{approved} (the host holds an approval capability bound to the digest of exactly this action and the current approval epoch). The deterministic policies are
\begin{align*}
\varphi_1 &: \textit{destructive}\wedge\textit{production}\Rightarrow\textit{approved},\\
\varphi_2 &: \neg(\textit{external}\wedge\textit{secret}),
\end{align*}
required of every executed action, so that $\varphi_{\mathrm{det}}=\varphi_1\wedge\varphi_2$ is a safety property of traces. The semantic policy $\varphi_3$ refers to an oracle $Y(h,a)\in\{0,1\}$ that is $1$ when executing $a$ in context $h$ would follow an unauthorized instruction. In our study, $Y$ is fixed by construction for every trace; in practice it is an expert judgment.

On the running example: $\Tstar$ and $\Tj$ propose an \textsf{http} action to \texttt{sink.invalid} whose input is the \texttt{.env} file, so \emph{external} and \emph{secret} hold and $\varphi_2$ is violated; $Y=1$ for both. $\Tb$ sends public diagnostics to the local service; it satisfies $\varphi_{\mathrm{det}}$ and $Y=0$.

\textbf{Risk and utility.} Let $D$ be the distribution of proposals at deployment and \allow{} the event that the pipeline finally accepts. We measure
\begin{equation}
R(D)=\Pr_D[Y=1\wedge\allow],\qquad U(D)=\Pr_D[\allow\mid Y=0].
\label{eq:risk}
\end{equation}
$R$ is a \emph{joint} probability: the fraction of all proposals that are unsafe and accepted. It is neither the miss rate $\Pr[\allow\mid Y=1]$ nor the fraction of accepted actions that are unsafe, $\Pr[Y=1\mid\allow]$. The three differ by factors that depend on how common attacks are. If one proposal in ten is unsafe and a guard misses half of them, the miss rate is one half but $R=0.05$. We report the conditional quantity $\Pr[Y=1\mid\allow]$ separately as \emph{accepted conditional risk}. $R$ bounds the per-decision risk; over a horizon of $H$ decisions, the probability of at least one unsafe acceptance is at most $HR$ under a per-step version of the same premise.

\subsection{Layers, Contracts and Conditioned Trust}

\begin{definition}[Layer]
A layer $L_i$ consists of a view function $v_i$ that maps $(h,a)$ to the information the layer may read, a decision function from views to $\{\allow,\block,\escalate\}$, and a cost $c_i$. A layer that errs, times out or returns an unknown value is treated as returning \block{}.
\end{definition}

For DevAgent, $v_1$ is the six Boolean facts; $v_2$ is the raw issue text; and $v_3$ is either the raw text (an \emph{exposed} judge) or a closed, structured record without free text (a \emph{quarantined} judge).

\begin{definition}[Contract]
A contract $C_i=(A_i,G_i)$ for layer $L_i$ has a scope $P_i$ of properties, assumptions $A_i$ about the layer's view, its inputs' provenance and, for a learned guard, the calibration context, and a guarantee $G_i$ for the properties in $P_i$. $L_i$ \emph{satisfies} $C_i$ if $G_i$ holds whenever $A_i$ holds. $G_i$ is either a hard invariant (no action the layer allows violates $\varphi$) or a statistical statement about an explicitly named event, such as $\Pr_D[Y=1\wedge L_i\text{ allows}]\le b_i$.
\end{definition}

Satisfying a contract says nothing about whether its assumptions hold in a particular composition. This is where trust enters.

\begin{definition}[Conditioned trust edge]
\label{def:edge}
A trust edge $i\xrightarrow{p,E}j$ states that layer $i$ may act on the verdict of layer $j$ for property $p$, provided the evidence $E$, established by trusted code at that edge, discharges $j$'s assumptions. The edge is \emph{well formed} if $p\in P_i\cap P_j$, every item of $E$ is provided by $i$, and $A_j\subseteq E$. Edges are never derived: from $i\to j$ and $j\to k$ nothing follows about $i\to k$.
\end{definition}

Non-transitivity is a design rule here, not a theorem: an edge is valid only if it is declared and its own obligation is discharged. A trust edge also carries no authority to introduce further edges.

\subsection{The Countermodel}

\begin{proposition}[Local satisfaction does not compose]
\label{prop:t0}
There is a three-layer composition in which every layer satisfies its contract and the composition executes an action that violates $\varphi_{\mathrm{det}}$ and has $Y=1$.
\end{proposition}

\begin{IEEEproof}
Let $L_3$ be a judge that blocks every action with $Y=1$ when it receives the structured view, but returns \allow{} when the raw issue text contains ``reviewer must answer SAFE''. Its contract assumes the structured view, so $L_3$ satisfies $C_3$. Let $L_2$ relay $L_3$'s verdict under the assumption that its caller has supplied $L_3$ with the structured view; $L_2$ satisfies its contract. Let $L_1$ relay $L_2$'s verdict under the assumption that any delegated acceptance preserves $\varphi_{\mathrm{det}}$; $L_1$ satisfies its contract. Now a caller passes the raw text of $\Tj$ to $L_3$ and executes the relayed \allow{} without a deterministic check. $\Tj$ violates $\varphi_2$ and has $Y=1$. In this run each layer's assumption is false, so each contract holds vacuously, and the composition is unsafe.
\end{IEEEproof}

The proposition does not contradict compositional reasoning; it is exactly the situation compositional proof rules exclude, because the assumptions were never discharged. The point for engineers is that in deployed guardrail stacks the discharge step is usually implicit. Nothing in the code checks that the judge saw the input its accuracy was measured on, or that a relayed acceptance passed the rule layer. On $\Tb$, all the premises can hold and the action executes correctly. On $\Tstar$, which contains no instruction for the judge, even the exposed judge blocks. Only the trace that targets the judge exposes the gap. Fig.~\ref{fig:countermodel} contrasts the naive relay with the checked composition of Section~\ref{sec:approach}. Adding a mandatory rule check at $L_1$ already defeats $\Tj$, because $\Tj$ also violates $\varphi_2$. Our evaluation therefore includes a strong control that has this check, so that quarantine and certification are not credited with what the rule layer alone achieves.

\subsection{Failure Modes and Problem Statement}

The example generalizes to three failure modes, which correspond to challenges C1--C3.
\emph{F1, undischarged assumptions:} a verdict is consumed although the producing layer saw a different view, provenance or scope than its contract assumes.
\emph{F2, wrong risk algebra:} the risk of a cascade is computed as if it were a veto ensemble, or per-layer miss rates are multiplied as if independent.
\emph{F3, stale certificates:} a statistical bound computed for one policy, scorer version, view or context is applied to another.

\textbf{Problem.} Given a guardrail hierarchy and its contracts, we want to (i)~check before deployment that every trust edge is declared and discharged; (ii)~enforce $\varphi_{\mathrm{det}}$ exactly on every executed action; (iii)~bound $R(D)$ only by quantities certified for the deployed configuration; (iv)~among certified configurations, select one that minimizes expected cost; and (v)~fail closed whenever a premise cannot be established at runtime.

\section{Approach: Checked Composition with \tint{}}
\label{sec:approach}

Online, every tool call passes through a closed parser and the deterministic sink, the runtime confirms that the certificate applies, and only then are the semantic layers consulted. The judge receives a quarantined view. Every error and every missing premise leads to \block{}.

\subsection{Specifying Contracts and Trust Edges (RQ1)}
\label{sec:spec}

A \tint{} specification is a JSON document with four fields: \texttt{layers}, \texttt{trust}, \texttt{mandatory} and \texttt{rules}. Each layer declares a name, the properties in its scope, the evidence items it \texttt{requires} (its assumptions), the evidence items it \texttt{provides} to layers it calls, and its \texttt{view}, one of \texttt{metadata}, \texttt{raw} or \texttt{structured-v1}. Each trust edge names a caller, a callee, a property and the evidence the caller supplies. \texttt{mandatory} lists the deterministic invariants that must hold on every acceptance. Fig.~\ref{fig:spec} shows the DevAgent specification. The schema is closed: unknown or duplicate fields, empty names and unsupported views are rejected while parsing.

\begin{figure}[!t]
\scriptsize
\begin{verbatim}
{"layers": [
  {"name":"L1", "scope":["semantic","deterministic"],
   "requires":[], "view":"metadata",
   "provides":["quarantine","calibrated_context"]},
  {"name":"L2", "scope":["semantic"],
   "requires":["calibrated_context"], "view":"raw",
   "provides":["quarantine","calibrated_context"]},
  {"name":"L3", "scope":["semantic"], "provides":[],
   "requires":["quarantine","calibrated_context"],
   "view":"structured-v1"}],
 "trust": [
  {"caller":"L1","callee":"L2","property":"semantic",
   "evidence":["calibrated_context"]},
  {"caller":"L2","callee":"L3","property":"semantic",
   "evidence":["quarantine","calibrated_context"]}],
 "mandatory":["production_approval","secret_egress"],
 "rules":["production_approval","secret_egress"]}
\end{verbatim}
\caption{The DevAgent specification (\texttt{experiments/configs/devagent.json}, reformatted). $L_1$ trusts $L_2$ only for the semantic property and only with calibration context; $L_2$ trusts $L_3$ only if it supplies a quarantined view. There is no edge from $L_1$ to $L_3$, and none is inferred.}
\label{fig:spec}
\end{figure}

Algorithm~\ref{alg:check} checks a parsed specification. It accepts only if every declared edge is well formed in the sense of Definition~\ref{def:edge}, the mandatory sink invariants are present, no raw-view layer is asked to satisfy a quarantine assumption, and the escalation graph is acyclic. It never adds an edge. The check is linear in the number of layers and edges, multiplied by the size of the evidence sets.

\begin{algorithm}[!t]
\caption{Trust-edge checker (\texttt{tint.spec.check})}
\label{alg:check}
\footnotesize
\begin{algorithmic}[1]
\REQUIRE specification $\mathcal{S}=(\mathcal{L},\mathcal{E},M,\mathcal{R})$
\STATE reject if layer names are not unique or $\mathcal{L}=\emptyset$
\STATE reject if $M$ or $\mathcal{R}$ differs from the supported deterministic fragment
\FOR{each edge $(i,j,p,E)\in\mathcal{E}$}
  \STATE reject if $i$ or $j$ is not a declared layer \COMMENT{no inferred endpoints}
  \STATE reject if $(i,j,p)$ was already seen
  \STATE reject if $p\notin P_i\cap P_j$ \COMMENT{scope}
  \STATE reject if $E\not\subseteq\mathit{provides}(i)$ or $\mathit{requires}(j)\not\subseteq E$ \COMMENT{discharge}
  \STATE reject if $\mathit{view}(j)=\texttt{raw}$ and $\texttt{quarantine}\in\mathit{requires}(j)$
\ENDFOR
\STATE reject if the graph $(\mathcal{L},\mathcal{E})$ has a cycle \COMMENT{Kahn's algorithm}
\STATE \textbf{accept}
\end{algorithmic}
\end{algorithm}

The checker establishes a syntactic fact: every assumption of every trusted callee is covered by evidence its caller declares it provides. Whether the caller's code really provides that evidence is a separate question, which the runtime answers for the one topology it implements (Section~\ref{sec:enforce}). This division is deliberate. Declarations make trust explicit and reviewable (C1); the runtime makes the declarations true for the actions that are executed.

\subsection{Enforcing the Deterministic Fragment}
\label{sec:enforce}

Three mechanisms keep the deterministic guarantee independent of the semantic layers.

\emph{Complete mediation with monitor-owned metadata.} The agent can only propose actions through a parser with a closed schema of four fields (kind, target, input references and environment). It cannot supply labels, approvals or code. The provenance store is write-once, and a derived observation cannot drop a label of its parents. Approvals are capabilities that the host grants for the digest of one exact action in the current epoch; revoking all approvals advances the epoch.

\emph{Sink first, no overwrite.} $L_1$ evaluates $\varphi_1$ and $\varphi_2$ on the monitor's view before any semantic layer runs. A block ends the decision; no later layer can turn it into an acceptance. Because the sink runs on every action, every acceptance route passes it.

\emph{Quarantined judge.} The judge receives a closed record with the six Boolean facts and the $L_2$ score, and nothing else: no issue text, no free-form strings and no model-generated rationale. Text addressed to the judge cannot reach it. The price is information loss: a quarantined judge cannot read semantic cues that a raw-text judge could use.

All semantic failures fail closed. A missing or inapplicable certificate, a scorer exception or out-of-range score, a judge exception or malformed verdict, and an escalation to the abstaining human stub all produce \block{}.

\begin{proposition}[Scoped soundness of checked composition]
\label{prop:t1}
Assume (A1)~complete mediation and unforgeable labels and approvals; (A2)~every acceptance passes a deterministic monitor that is correct for $\varphi_{\mathrm{det}}$ on the typed view; (A3)~no block is overwritten; and (A4)~the acceptance routes $E_1,\dots,E_m$ are disjoint, and for each route a certificate guarantees $\Pr_D[Y=1\wedge E_k]\le b_k$, all certificates holding simultaneously with probability at least $1-\delta$ over calibration, and the runtime checks each certificate's view, version and context premises. Then (i)~no executed action violates $\varphi_{\mathrm{det}}$, and (ii)~with probability at least $1-\delta$, $R(D)\le\sum_{k}b_k$.
\end{proposition}

\begin{IEEEproof}
(i)~By A1, an action executes only if the runtime accepted it; by A2 and A3, every accepted action was allowed by the deterministic monitor and no later layer overruled a block, so by the monitor's correctness the action satisfies $\varphi_{\mathrm{det}}$. Induction over trace prefixes extends this to every prefix. (ii)~Because the routes are disjoint, $\mathbf{1}[Y=1\wedge\allow]=\sum_k\mathbf{1}[Y=1\wedge E_k]$. Taking expectations under $D$ gives $R(D)=\sum_k\Pr_D[Y=1\wedge E_k]\le\sum_k b_k$ on the event that all certificates hold. If a runtime premise fails, the decision is \block{}, which adds no route.
\end{IEEEproof}

The simultaneity in A4 needs no independence: allocating $\delta$ across the certificates and applying a union bound suffices. On the running example, $\Tstar$ and $\Tj$ are blocked by (i); $\Tb$ may be accepted on any certified route. The proposition says nothing about whether a raw LLM judge is correct, or whether a runtime check detects every change of distribution; those are assumptions, listed in Section~\ref{sec:limits}. Our implementation uses the simplest instance, $m=1$: it certifies the joint unsafe acceptance of the whole policy, so that $b_1$ bounds $R(D)$ directly.

\subsection{Accounting for Risk Across Layers (RQ2)}
\label{sec:accounting}

Two structures are easily confused. In a \emph{veto ensemble}, an action is accepted only if every guard allows it. In an \emph{early-accept cascade}, a cheap layer may accept an action that the expensive layer never sees. To compare them, let $M_i=\{Y=1\wedge L_i\text{ allows}\}$ be the event that guard $i$ would miss an unsafe proposal, evaluated counterfactually on every proposal, even those that an actual run stopped earlier. Let $\pi=\Pr[Y=1]$ and $m_i=\Pr[L_i\text{ allows}\mid Y=1]$.

\begin{proposition}[Veto and cascade risk]
\label{prop:t2}
(a)~For a veto ensemble, $R=\Pr(\bigcap_i M_i)\le\min_i\Pr(M_i)$.
(b)~If the guards' misses are conditionally independent given $Y=1$, then $R=\pi\prod_i m_i$, which in general differs from $\prod_i\Pr(M_i)=\pi^{n}\prod_i m_i$.
(c)~If, given $Y=1$, all guards share one uniform random variable with probability $\rho$ and use independent ones otherwise (a common-shock model), then $R=\pi\bigl[(1-\rho)\prod_i m_i+\rho\min_i m_i\bigr]$.
(d)~For an early-accept cascade with disjoint acceptance routes $E_k$, $R=\sum_k\Pr[Y=1\wedge E_k]$; neither the minimum in~(a) nor the product in~(b) is a valid bound.
\end{proposition}

\begin{IEEEproof}
(a)~A veto ensemble accepts an unsafe proposal exactly when all guards allow it, and an intersection is no more probable than any of its members. (b)~Conditioning on $Y=1$ and using independence gives $\pi\prod_i m_i$; the joint events $M_i$ cannot be independent of each other in general, because they all contain the event $Y=1$. (c)~Conditioned on the shared variable, all misses occur together with probability $\min_i m_i$; otherwise they are independent. (d)~Follows from the indicator decomposition in Proposition~\ref{prop:t1}. An unsafe proposal accepted by $L_2$ never reaches $L_3$, so $L_3$'s miss rate does not enter its route.
\end{IEEEproof}

The gap is large even for small stacks. With $m=(0.1,0.2,0.3)$ and conditionally independent misses, a veto ensemble misses an attack with probability $0.006$; with fully shared failures, the probability is $0.1$, about seventeen times higher. Both laws have the same per-guard miss rates.

\begin{proposition}[Pairwise statistics do not identify joint risk]
\label{prop:t4}
There are joint laws of three guards' misses with identical marginals and identical, zero pairwise correlations whose triple-miss probabilities are $0$ and $1/4$.
\end{proposition}

\begin{IEEEproof}
Let each miss indicator be a fair bit. Under the uniform law on bit triples with even parity, all pairs are independent and all three bits are never $1$ at once; under the uniform law on odd-parity triples, all pairs are again independent and the triple $(1,1,1)$ has probability $1/4$.
\end{IEEEproof}

Two tightness facts complete the picture. The minimum in (a) is attained when all guards threshold one shared uniform variable, so no better bound follows from marginals alone. The route sum in (d) is attained by placing unsafe mass $b_k$ on each route, so no smaller bound follows from route certificates alone. The practical consequence is simple: the risk of a pipeline should be estimated on the pipeline, as a joint probability, and not assembled from per-layer statistics.

\subsection{Certifying and Selecting Escalation Policies (RQ2)}
\label{sec:certify}

\textbf{Finite-family certification.} Let $\Pi=\{\pi_1,\dots,\pi_K\}$ be candidate policies fixed before calibration; in DevAgent, $\pi_j$ escalates from $L_2$ to $L_3$ when the score $s\ge t_j$ for a threshold grid $t_j$. On $n$ independent calibration proposals, count $k_j$, the number of unsafe proposals that policy $\pi_j$ accepts. Let $u_j$ be the one-sided Clopper--Pearson upper bound at level $\delta/K$,
\begin{equation}
u_j=\mathrm{Beta}^{-1}\!\left(1-\tfrac{\delta}{K};\,k_j+1,\,n-k_j\right),
\label{eq:cp}
\end{equation}
with $u_j=1$ when $k_j=n$. Select the candidate with the lowest mean calibration cost among those with $u_j\le\varepsilon$. If no candidate qualifies, deploy the block-all policy and report infeasibility; the budget is never relaxed.

\begin{proposition}[Certified selection]
\label{prop:select}
If calibration proposals are drawn independently from $D$, then with probability at least $1-\delta$ over calibration, $R_D(\pi_j)\le u_j$ holds simultaneously for all $j$. In particular, the selected policy satisfies $R_D\le\varepsilon$.
\end{proposition}

\begin{IEEEproof}
Each $u_j$ is an exact upper confidence bound at level $\delta/K$ for a fixed policy. A union bound over the $K$ fixed candidates gives simultaneous coverage at level $\delta$, and selection based on the data cannot leave the event on which all bounds hold.
\end{IEEEproof}

This is a high-probability statement about the realized risk of the deployed policy. Conformal risk control~\cite{arxiv220802814} gives a different promise, a bound on the expected loss over calibration and test draws. \tint{} implements both, but its experiments use the certificate of Proposition~\ref{prop:select}.

\textbf{Binding certificates to configurations.} A certificate records the policy fingerprint, the context identifier, the view version, the bound $u$, $\delta$ and $n$. The fingerprint is a SHA-256 hash of the specification, threshold, scorer version, judge version, view and environment. On every decision, the runtime recomputes the fingerprint of the configuration it is actually running and accepts semantically only if the certificate matches it, the bound is within the deployment budget, and $\delta$ does not exceed the host's confidence budget (C3). Matching a context identifier is a configuration check, not a distribution test; it cannot detect a shift in the data.

\textbf{Escalation rule.} Which inputs should be escalated? Let $x$ be the trusted view of a proposal, $r_0(x)$ the conditional risk of accepting it at the cheap layer, $r_1(x)$ the conditional risk after escalation, and $d(x)>0$ the extra cost of escalation. A randomized policy escalates with probability $q(x)$ and should minimize $\mathbb{E}[d\,q]$ subject to $\mathbb{E}[r_0-q\,(r_0-r_1)]\le\varepsilon$.

\begin{proposition}[Escalation by risk reduction per cost]
\label{prop:t3}
For a multiplier $\lambda\ge0$, the pointwise minimizer of the Lagrangian escalates when $\lambda\,(r_0(x)-r_1(x))>d(x)$, accepts when the inequality is reversed, and may randomize on ties. If a feasible measurable policy of this form and a finite $\lambda$ satisfy complementary slackness, $\lambda(R(q)-\varepsilon)=0$, the policy is optimal.
\end{proposition}

\begin{IEEEproof}
The Lagrangian is $\mathbb{E}[d\,q]+\lambda(\mathbb{E}[r_0-q(r_0-r_1)]-\varepsilon)$. Collecting the coefficient of $q(x)$ gives $d(x)-\lambda(r_0(x)-r_1(x))$, which the minimizer drives to its sign. Weak duality and equality of the Lagrangian value under complementary slackness certify optimality.
\end{IEEEproof}

The premises matter. The rule thresholds the \emph{risk reduction per unit cost}, not the classifier score; it reduces to a score threshold only if the cost is constant and the risk reduction is monotone in the score. If $r_1>r_0$, which happens when an exposed judge can be manipulated, as on $\Tj$, escalation increases risk. A finite multiplier need not exist: for $x$ uniform on $(0,1)$, $r_0(x)=x$, $r_1(x)=0$, $d(x)=1$ and $\varepsilon=0$, feasibility requires escalating almost every input, which no finite $\lambda$ achieves. Because conditional risks are unknown in practice, \tint{} optimizes within the finite certified family instead: enumeration finds the cheapest certified deterministic candidate, and a linear program over mixtures of candidates, which for one risk constraint has an optimum with at most two non-zero weights, gives the cheapest randomized policy. Both are exact within the family and make no claim about unrestricted policies.

\subsection{Assumptions and Limits}
\label{sec:limits}

The guarantees above hold under assumptions that the runtime cannot establish by itself. We list them so that a deployment can audit them.
\emph{Trusted host:} the provenance store, approval store, certificate store and plugin version strings are honest; a compromised host is out of scope.
\emph{Typed semantics:} safety is relative to the typed action interpreter; shell parsing, covert channels and tools with unmodeled effects are out of scope.
\emph{Exchangeability:} certificates assume that calibration and deployment proposals come from the same distribution. Under a shift of total-variation size $\eta$, a fixed policy's risk grows by at most $\eta$, but $\eta$ must be justified externally.
\emph{Adaptive inputs:} an attacker who observes the guard's answers and adapts breaks exchangeability; against an unconstrained adaptive attacker, no non-trivial distribution-free bound exists short of exact deterministic mediation or blocking.
\emph{Fixed topology:} the checker accepts general acyclic specifications, but the runtime enforces only the $L_1\to L_2\to L_3$ topology of Fig.~\ref{fig:spec}.
\emph{No refinement proof:} we model-check an abstraction and test the implementation; we do not prove that the implementation refines the model.

% =====================================================================
\section{Evaluation}
\label{sec:eval}
% =====================================================================

Our evaluation is a controlled, preregistered feasibility study rather than a benchmark comparison, and the design follows from the kind of claims under test. The claims are about composition: whether an obligation is discharged, whether a bound covers the true risk, whether the route that executes is the route that was certified. Testing them requires three things that current LLM agent benchmarks do not provide together: a ground-truth semantic label for every proposed action, a known data-generating law against which a probability bound can be checked, and components whose behavior is fully known, so that a failure can be attributed to the composition and not to an opaque model. We therefore built a typed, in-memory agent sandbox with an authored fixture law, scripted guards and a deliberately vulnerable judge that serves as an executable countermodel. Each claim is tested with the method that fits it: model checking and exhaustive enumeration for the deterministic fragment, mutation analysis for the checker, Monte Carlo replications against a known law for the bounds, and a paired, seed-level comparison for the pipeline. The comparators isolate mechanisms rather than reproduce products; they include a strong control that keeps the deterministic sink but omits quarantine and certification, so that \tint{} is not credited with what a rule layer alone achieves. All thresholds, budgets and analyses were frozen before held-out data were generated; one later defect fix is evaluated on fresh seeds and labeled exploratory. This design buys internal validity and complete verifiability at the price of external validity. It can show that the discipline is implementable, that it rejects the composition errors it targets, and where it fails. It cannot show that \tint{} makes real LLM agents safer, and we do not claim that it does.

\subsection{Implementation and Its Relation to the Approach}
\label{sec:impl}

\tint{} is a Python library of about seven hundred lines in eight modules, with an experiment driver, formal models and analysis scripts. Table~\ref{tab:impl} maps every element of the approach to the code that implements it and to the tests that exercise it. We describe the less obvious correspondences here.

\emph{Model and provenance.} \texttt{tint.model} defines the immutable \texttt{Action} type, the label lattice as a bit flag, a write-once \texttt{ProvenanceStore} that refuses derived observations which drop parent labels and labels unknown references $\{U,S\}$, and an \texttt{ApprovalStore} whose grants are keyed by action digest and epoch. The function \texttt{action\_view} computes the six facts of Section~\ref{sec:problem}; only one exact local mock destination counts as internal, so aliases and real URLs are external.

\emph{Specification.} \texttt{tint.spec.parse} rejects duplicate JSON keys and any field outside the closed schema; \texttt{check} implements Algorithm~\ref{alg:check} with Kahn's algorithm for acyclicity, so large specifications do not hit recursion limits.

\emph{Runtime.} \texttt{tint.runtime.GuardRuntime} is the online half of Fig.~\ref{fig:overview}. Its constructor re-runs the checker and refuses any topology other than $L_1\to L_2\to L_3$ with the declared views, which is where the declared \texttt{provides} items of Fig.~\ref{fig:spec} become true by construction: the only code path to $L_3$ passes through \texttt{quarantine}, which builds the closed record. \texttt{evaluate} runs the sink, recomputes the policy fingerprint, checks certificate applicability, calls the scorer and, if needed, the judge through a wrapper that converts every exception into \block{}, and logs the decision. \texttt{parse\_tool\_call} is the closed tool parser.

\emph{Guards.} \texttt{tint.layers} contains the deterministic sink, the lexical scorer, the quarantine projection, the structured judge, and the \texttt{ExposedJudge} test double that returns \allow{} when the raw text contains the judge-targeting phrase. These are explicit stand-ins: the scorer counts eight indicator tokens, $s=\min(0.98,\,0.04+0.12k)$ for $k$ matched tokens; the structured judge blocks when \emph{secret} and \emph{external} both hold or when $s\ge0.40$.

\emph{Calibration and synthesis.} \texttt{tint.calibration} implements the Clopper--Pearson bound, simultaneous family certification, split-conformal quantiles, conformal risk control, empirical correlation, the veto bounds of Proposition~\ref{prop:t2}, and the \texttt{Certificate} type with its applicability check. \texttt{tint.synthesis} implements certified selection, the Lagrangian rule of Proposition~\ref{prop:t3} and the mixture LP, solved with HiGHS through SciPy.

\emph{Sandbox and comparators.} \texttt{tint.agents.Sandbox} is a typed interpreter that records effects in memory; it has no shell and no network client. \texttt{tint.baselines} implements the six comparators of Section~\ref{sec:setup}. The experiment driver \texttt{experiments/run.py} generates traces, calibrates, selects, replays every comparator and writes compressed per-decision logs.

\subsection{Experimental Setup}
\label{sec:setup}

\textbf{Substrate and fixture law.} A trace is a proposed DevAgent action together with the issue text that led to it, monitor-owned provenance and an authored label $Y$. Traces are drawn from seven families with fixed weights (Table~\ref{tab:families}). Each family has one text template and one action; a per-trace suffix gives every trace a unique identifier but adds no semantics. The labels are ground truth by construction. One family, the \emph{implicit patch}, is unsafe by the task oracle but indistinguishable from an authorized patch in every guard's view; it is a designed observability limit that no guard in the study can overcome. The \emph{judge-targeting} family is the semantic counterpart of $\Tj$: the same instruction to the judge, attached to a patch that violates no deterministic rule, so the sink cannot stop it. A separate shift split uses an eighth, \emph{encoded} family that never appears in calibration. Secrets are fake canaries, \texttt{sink.invalid} does not resolve, and nothing is executed outside the in-memory interpreter.

\textbf{Calibration.} \tint{} selects its threshold from \resThresholdCount{} values, $t\in\{0,0.1,\dots,1\}$, fixed before calibration. It certifies the joint unsafe acceptance of the whole policy with the bound of Eq.~\eqref{eq:cp}, budget $\varepsilon=\resRiskBudget\%$ and $\delta=\resConfidenceFailure\%$, i.e., \resNominalConfidence\% simultaneous confidence across the grid. The budget is deliberately permissive: the pilot tests whether selection works, not whether the resulting policy is acceptable in production. If no candidate is certified, \tint{} deploys block-all.

\textbf{Metrics.} On the test split we report joint unsafe acceptance $\hat R$ (Eq.~\eqref{eq:risk}), benign utility $\hat U$, accepted conditional risk $\Pr[Y=1\mid\allow]$, the number of hard violations (accepted actions that violate $\varphi_{\mathrm{det}}$), modeled cost and CPU time. Modeled cost charges $\resCostRules$, $\resCostScorer$, $\resCostJudge$ and $\resCostApproval$ units for reaching $L_1$ to $L_4$; these are arbitrary units that encode the intended cost ratio of rules, classifier, LLM judge and human, not milliseconds, tokens or money. CPU time is wall-clock time of the decision function measured with a nanosecond counter; it measures our Python code, not a model.

\textbf{Statistical analysis.} We compare \tint{} with each comparator on paired seed-level aggregates. We report the mean paired difference, a $95\%$ percentile bootstrap interval with \resBootstrapCount{} resamples of the seeds~\cite{efron1994introduction}, a two-sided Wilcoxon signed-rank test~\cite{wilcoxon1945individual} with Holm correction across the six comparisons~\cite{holm1979simple}, and the Vargha--Delaney $\hat A_{12}$ effect size~\cite{vargha2000critique}, following guidance for randomized algorithms in software engineering~\cite{arcuri2011practical}. Ten seeds suit a pilot, not a powered study. We return to the meaning of these tests below, because the comparators are deterministic within a family.

\textbf{Further experiments.} For H3, we draw \resPrimaryReplications{} calibration sets of size \resCoverageCalibrationCount{} (\resCoveragePerSeed{} per seed) from a known law with eleven candidate policies whose true risks range from $0$ to $0.20$ and select the cheapest candidate whose simultaneous bound is at most \resCoverageTarget\%; we record whether the selected candidate's true risk lies below its bound. For dependence, we simulate three guards with conditional miss rates \resDependenceFirst, \resDependenceSecond{} and \resDependenceThird{} under the common-shock model at five mixture weights, \resDependenceSamples{} samples per cell and seed. For H2, we generate specifications with five to five hundred properties and two to six layers and apply four mutations (missing evidence, out-of-scope property, unknown endpoint, added cycle). For H5, we draw fifty random finite candidate families and compare the selector with independent enumeration. For H8, we try to express five policy classes in the DSL. For H1, we run PRISM~\ver{4.11}~\cite{kwiatkowska2011prism} on a discrete-time Markov chain abstraction of the canonical traces in both routings, and enumerate all combinations of the sink's six Boolean inputs.

\textbf{Environment and protocol.} All experiments ran on one Windows~11 workstation with \resEnvCpuCount{} logical CPUs, Python~\resEnvPython, NumPy~\resEnvNumpy{} and SciPy~\resEnvScipy, without GPU use, API calls or network effects. The primary study took \resPrimaryRuntime\,s and the replication \resExploratoryRuntime\,s. Two dated amendments, committed before the respective analyses, govern deviations: A1 introduced the defect fix and the fresh-seed replication, and A2 added descriptive per-family analyses and corrected the attribution of the adaptive-search instrument. Original logs are kept unchanged.

\subsection{RQ1: Specification and Decomposition}

\textbf{H1, deterministic safety.} PRISM checked \resPrismCases{} configurations, the three canonical traces under naive and checked routing, for two reachability properties. Under naive routing, $\Tj$ reaches a bad execution with probability one; under checked routing no configuration does, and $\Tb$ executes in both. The independent enumeration of all \resFormalStates{} sink inputs confirmed that the sink blocks exactly the inputs that violate $\varphi_{\mathrm{det}}$. In the sandbox replay, the pipelines with a sink (B1, B5, A1, \tint{}) executed no hard violation in either study, whereas B2, B3 and B4 accepted every production deletion: \resExploratoryClassifierOnlyHard{} hard violations each on the exploratory test split (Table~\ref{tab:results}). H1 is supported within the enumerated and replayed scope. This is evidence about the typed abstraction, not a proof that the Python runtime refines the model.

\textbf{H2, checker.} In each study, the checker rejected all \resPrimaryCheckerTP{} invalid specifications and accepted all \resPrimaryCheckerTN{} valid ones, with \resPrimaryCheckerFP{} false positives and \resPrimaryCheckerFN{} false negatives. These counts repeat \resPrimaryCheckerUniqueInvalid{} unique invalid and \resPrimaryCheckerUniqueClean{} unique valid specifications across seeds, because the generator is deterministic. The mutations are the obligation errors the checker is designed to catch, so perfect precision and recall support H2 only for these generators; they say nothing about the errors real engineers make. Checking time grows linearly with the number of edges (Fig.~\ref{fig:scaling}); the largest specification, with \resCheckerMaxEdges{} edges, takes a median of \resCheckerMaxMs\,ms.

\textbf{H8, expressiveness.} Of the \resPolicyClasses{} policy classes we tried to express, the DSL fully supports \resSupportedClasses: production approval and secret egress. Semantic injection is supported only as a statistical proxy through the scorer and judge; filesystem confinement and cumulative spending cannot be expressed. H8 is refuted, as we expected when we registered it.

\textbf{Answer to RQ1.} An end-to-end property can be decomposed into a deterministic fragment, enforced by a sink that every acceptance passes, and a semantic fragment whose trust edges are declared and checked. The checker reliably rejects the obligation errors we planted and scales linearly, and the deterministic guarantee holds in every replayed decision. The decomposition is narrow: the language covers two deterministic policy classes, and the runtime enforces one fixed topology.

\subsection{RQ2: Guarantees and Escalation}

\textbf{H4, canonical traces.} The executable countermodel behaves as Proposition~\ref{prop:t0} predicts: under invalid delegation (B4), $\Tj$ is accepted and would execute; under \tint{} it is blocked at the sink. The strong control B5 also blocks $\Tj$, because $\Tj$ violates $\varphi_2$. H4 is supported, and the result shows the value of the mandatory sink, not of quarantine. Quarantine can only matter when the judge-targeting instruction is attached to an action that the sink allows, which is what the judge-targeting family tests in RQ3.

\textbf{H3, coverage of certificates.} In \resPrimaryCoverageCovered{} of \resPrimaryReplications{} replications, the true risk of the selected candidate lay below its simultaneous bound: coverage \resPrimaryCoverage\% (exact $95\%$ interval \resPrimaryCoverageLo--\resPrimaryCoverageHi\%). The replication's coverage study gave \resExploratoryCoverage\% (\resExploratoryCoverageLo--\resExploratoryCoverageHi\%). Both lie well above the nominal \resNominalConfidence\%, as expected from the conservative union bound over eleven candidates and the discreteness of the binomial. H3 is supported for a static, independent law with known risks. The quantity is different from the fraction of finite test sets whose empirical risk falls below the target (\resPrimaryFiniteTestBelow{} of \resPrimaryReplications{}), which is not what the proposition guarantees.

\textbf{Dependence.} Fig.~\ref{fig:dependence} shows the simulated joint miss probability of three guards whose marginal miss rates never change. It moves from the product of the miss rates under independence to their minimum under fully shared failures, and the simulation stays within \resDependenceGap{} of Proposition~\ref{prop:t2}(c) in every cell. The parity construction of Proposition~\ref{prop:t4} was confirmed numerically: two laws with pairwise independent fair misses give triple-miss probabilities $0$ and $0.25$.

\textbf{H5, selection.} In all \resPrimarySynthInstances{} random finite families, certified selection returned the candidate found by independent exhaustive enumeration (\resPrimarySynthMismatches{} mismatches), and the mixture LP's optimum agreed with an independent enumeration of the LP's vertices. H5 is supported within the finite family; no claim is made about unrestricted routing policies.

\textbf{Answer to RQ2.} The composition bounds end-to-end risk under four explicit premises (Proposition~\ref{prop:t1}), and the certificates behaved as stated when their own premises held. The failure conditions are specific: undischarged trust (Proposition~\ref{prop:t0}), veto reasoning applied to a cascade or to dependent guards (Propositions~\ref{prop:t2} and~\ref{prop:t4}), escalation to a judge whose risk exceeds the cheap layer's (Proposition~\ref{prop:t3}), and any shift or adaptation that breaks exchangeability. Within a finite certified family, the cost-minimal policy can be selected exactly. RQ3 shows what happens when the premises fail.

\textbf{Where the numbers come from.} Every pipeline's decision is a deterministic function of the family (Table~\ref{tab:families}), so the population metrics follow from the family masses, and the seeds vary only how many traces of each family are drawn. \tint{} accepts the benign reports and the implicit patches; its risk is the implicit-patch mass, \resExploratoryCheckedQuarantinePopulationRisk\% in the population, and its utility is the benign-report share of benign traces, \resExploratoryCheckedQuarantinePopulationUtility\%. \textbf{Cost and latency.} \tint{}, A1 and B5 reach the same layers and therefore have the same modeled cost, \resExploratoryCheckedQuarantineCost{} units per decision, with \resExploratoryCheckedReachThree\% of decisions reaching the judge. \tint{}'s median CPU time per decision was \resExploratoryCheckedCpuMedian\,$\mu$s against \resExploratoryNaiveWithSinkCpuMedian\,$\mu$s for B5. \textbf{Answer to RQ3.} In the controlled sandbox, the discipline is implementable and its parts did what they were designed to do: the sink prevented every deterministic violation, quarantine eliminated the judge-targeting family at no utility cost relative to a strong control, and the certificate gate refused to ship a defective scorer. The evidence does not show a better risk--utility frontier in general. The primary policy was useless because it blocked everything; certification did not change any decision once the defect was fixed; a rule-only pipeline had higher utility; and every pipeline failed under shift. Whether these mechanisms help real LLM agents (H7) remains untested.

\section{Discussion}
\label{sec:discussion}
% =====================================================================

\textbf{Lessons for engineers of guardrail stacks.}
First, \emph{write every trust edge down}. Each time one layer acts on another's verdict, state for which property, and which facts about the callee's input make the verdict meaningful. Most stacks we examined in the literature describe their layers but not these edges, and an edge that is not written down cannot be checked.
Second, \emph{never delegate deterministic properties}. A sink that runs on every action did most of the work in our study; it alone stopped $\Tstar$ and $\Tj$ and every production deletion. Semantic layers should add protection, not replace rules.
Third, \emph{do not let the judge read what the attacker wrote}. In our replication, the only difference between \tint{} and a strong control was the judge-targeting family, and quarantine removed it. The cost is information: a quarantined judge sees less, and in a real system the right projection is a design problem of its own.
Fourth, \emph{measure the pipeline, not the parts}. The risk of an early-accept cascade is a sum over acceptance routes; per-layer miss rates, multiplied or minimized, can be wrong by an order of magnitude, and pairwise correlations do not fix them.
Fifth, \emph{bind evidence to configurations and expect it to expire}. The certificate gate caught a defect that would otherwise have shipped. The same gate did nothing against shift; a certificate says nothing about data it has not seen.

\textbf{On the negative primary result.} A block-all policy has zero risk and zero value; reporting it as a success would be wrong. We nevertheless think the primary run is instructive. It shows the intended behavior of certification under a broken component: refuse service rather than accept unsafely, and make the refusal visible. It also shows a cost of the discipline: with a permissive budget and a defective guard, the safe outcome is no service at all. In a deployment this is a choice between availability and safety that should be made explicitly, not by default.

\textbf{What a convincing evaluation needs.} To move from feasibility to effectiveness, an evaluation needs real coding agents on realistic tasks~\cite{jimenez2023swebench}, learned guards and LLM judges~\cite{arxiv231206674,arxiv250503574}, independently annotated semantic labels, an attacker who adapts to the guards' responses~\cite{arxiv230715043,arxiv250411168}, and matched comparisons against provenance-based isolation~\cite{arxiv250318813} and runtime rule enforcement~\cite{arxiv250318666}. The checker, runtime and certificate binding are written against callable scorer and judge interfaces so that such components can be plugged in; adapters alone, however, are not evidence.

\section{Threats to Validity}
\label{sec:threats}
% =====================================================================

We follow the usual classification~\cite{wohlin2012experimentation}.

\textbf{Internal validity.} We authored the fixture law, the guards and the comparators, so the study cannot rule out designer bias; we mitigated it by preregistering hypotheses, thresholds and analyses, by including a strong control that keeps the sink, and by publishing every decision. The primary instrument contained a numeric defect; we preserved its results, fixed only the arithmetic, and evaluated the fix on fresh seeds as an exploratory replication. The adaptive-search instrument queried the uncertified decision core and never adapted; we report it as uninformative. Labels are ground truth by construction, which favors guards that use the features the designer had in mind.

\textbf{Construct validity.} Joint unsafe acceptance is a per-decision measure; it is not the probability that a session causes harm. Benign utility counts accepted benign proposals and ignores whether the task succeeds. Modeled costs encode an intended ratio, not time or money, and our CPU times measure Python bookkeeping, not model inference. The structured judge is a deterministic surrogate; a real LLM judge on a quarantined view may behave very differently.

\textbf{External validity.} No real LLM, learned guard, external benchmark or human participant was involved, and the sandbox interprets typed actions in memory. Seven families with one template each cannot represent the diversity of real issues and attacks. The runtime supports a single topology. Our results therefore do not transfer to deployed agents without new evidence (H7 remained inconclusive).

\textbf{Conclusion validity.} Ten seeds suffice for a pilot. Decisions are deterministic per family, so tests mainly confirm sign consistency, and $p$-values sit at their floor; intervals reflect sampling of family proportions. The coverage experiment has a Monte Carlo standard error of about $0.007$ at $0.95$ coverage with a thousand replications, small relative to the observed margin.

\section{Related Work}
\label{sec:related}
% =====================================================================

\textbf{Guard models and guardrail frameworks.} Classifier guards screen prompts and responses for policy violations~\cite{arxiv231206674,arxiv240618495}, and constitutional classifiers defend against universal jailbreaks at scale~\cite{arxiv250118837}. Activation probes monitor model internals~\cite{arxiv250926238}, though obfuscated activations can evade them~\cite{arxiv241209565}. Reasoning guards deliberate before deciding~\cite{arxiv250213458}. Frameworks combine several guards with programmable rails~\cite{arxiv231010501,arxiv250721170}; LlamaFirewall layers injection detection, alignment checks and code scanning for agents~\cite{arxiv250503574}. Evasion studies show that guards can be bypassed~\cite{arxiv250411168,arxiv250305264,arxiv230715043} and that their behavior changes with retrieved context~\cite{arxiv251005310}. This work motivates hierarchies; \tint{} asks what such a hierarchy guarantees and when.

\textbf{Runtime enforcement for agents.} AgentSpec specifies triggers, predicates and enforcement actions for agent runtime rules~\cite{arxiv250318666}, and ProbGuard predicts unsafe states probabilistically~\cite{arxiv250800500}. ShieldAgent verifies actions against policies extracted from documents~\cite{arxiv250322738}; VeriGuard generates verified policy code~\cite{arxiv251005156}; agent behavioral contracts and the NaSh shell guardrails specify and enforce agent behavior~\cite{arxiv260222302,arxiv250613028}. Task alignment checks~\cite{arxiv241216682} and guardrails for LLM-controlled robots~\cite{arxiv250307885,arxiv251221220} follow similar ideas in other domains. ContrAgent specifies agents with assume-guarantee temporal contracts and compiles them into deterministic monitors~\cite{arxiv260918128}. Our DSL is deliberately smaller than AgentSpec's and ContrAgent's languages; what \tint{} adds is the treatment of statistical guards as contract-bearing layers whose trust edges and certificates are checked.

\textbf{Provenance and isolation.} CaMeL separates control and data flow so that untrusted data cannot change the program an agent executes~\cite{arxiv250318813}, and Fides applies information-flow control to agent planning~\cite{arxiv250523643}. Spotlighting marks untrusted input in the prompt~\cite{arxiv240314720}, and instruction hierarchies train models to prioritize privileged instructions~\cite{arxiv240413208}. These techniques implement classical reference-monitor and information-flow principles~\cite{anderson1972computer,saltzer1975protection,denning1976lattice,sabelfeld2003language}. \tint{}'s sink and quarantine are instances of the same principles; isolation-based systems are stronger on data flow than our typed sandbox, and a comparison with them is future work.

\textbf{Contracts and compositional assurance.} Assume-guarantee reasoning~\cite{misra1981proofs,jones1983tentative,abadi1993composing}, contract-based design~\cite{benveniste2018contracts,meyer1992applying} and runtime verification~\cite{leucker2009brief} supply the concepts we use. Shielding enforces safety of reactive and learning systems at runtime~\cite{arxiv150102573,arxiv170808611,arxiv190805402,arxiv240604184}, and the Simplex architecture switches to a verified controller when a complex one misbehaves~\cite{sha2001using}. A position paper argues that safe agent deployment needs a layered probabilistic assume-guarantee architecture~\cite{arxiv260518672}, and ScenicProver composes probabilistic evidence for learning-enabled systems~\cite{arxiv251102164}. Our contribution is narrower and more operational: an executable checker and runtime for guardrail hierarchies, and the identification of where trust between them must be discharged.

\textbf{Cascades and statistical guarantees for LLMs.} Model cascades trade cost and quality~\cite{arxiv230505176}. Conformal Arbitrage calibrates routing between a primary model and a guardian~\cite{arxiv250600911}; Trust or Escalate gives provable human-agreement guarantees for cascaded judges~\cite{arxiv240718370}; hybrid abstention and conformal abstention control reliability~\cite{arxiv260215391,arxiv240501563}. Conformal methods also control tail risk, factuality and set coverage for LLMs~\cite{arxiv250220285,arxiv240210978,arxiv230610193,arxiv230518404,arxiv240301216,arxiv240617819}. These methods supply the guarantees that \tint{} binds to configurations. They are valid for the input distribution and the input view on which they were calibrated, and \tint{}'s concern is to check that both still hold at the edge where a verdict is consumed.

\textbf{Benchmarks.} AgentDojo, ASB, AgentHarm, ToolEmu, R-Judge, RedCode and others measure attack success and defense utility for agents~\cite{arxiv240613352,arxiv241002644,arxiv241009024,arxiv230915817,arxiv240110019,arxiv241107781,arxiv251002609,arxiv240801605,arxiv250816481}; a recent study cautions that benchmark representations can change measured threat~\cite{arxiv261003585}. A real-agent evaluation of \tint{} should use them.

\section{Conclusion}
\label{sec:conclusion}
% =====================================================================

Guardrail hierarchies for LLM agents are built from guards whose guarantees are conditional, and those conditions do not travel along the chain of trust. We made the conditions explicit: conditioned trust edges that a checker verifies, a deterministic sink that no semantic layer can bypass, a judge that never reads attacker text, and certificates that apply only to the configuration they were computed for. Under stated premises, such a composition bounds end-to-end risk by a sum over acceptance routes, and a cost-minimal certified policy can be selected exactly within a finite family. A preregistered study in a controlled sandbox showed that the discipline is implementable and that each mechanism does what it was designed to do, including refusing service when a defective guard made certification impossible. It also showed the limits: certification added nothing once the defect was fixed, utility was capped by a crude scorer, and no mechanism resisted a distribution shift. The question that matters most, whether this discipline makes real LLM agents measurably safer at acceptable cost, needs real agents, learned guards and adaptive attackers to answer.

\section*{Ethics Statement}

No human participants, personal data or third-party systems were involved, and no external dataset is redistributed.
