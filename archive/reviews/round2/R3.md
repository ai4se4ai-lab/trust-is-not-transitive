# R3 — agent safety/security referee, round 2

## Five-sentence summary

TINT combines explicit delegation obligations, mandatory typed-action mediation, restricted judge views, and fixed-family risk certification in a local feasibility artifact. The revision materially improves the correspondence between implemented checks, trusted-host premises, historical observations, and empirical claims. In particular, it corrects the attribution of the fixed-threshold search, exposes family-level decisions and analytically implied results, and explicitly disclaims plugin cancellation and implementation refinement. These corrections improve scientific reliability but add no evidence of learned-guard behavior, real development-task success, production provenance completeness, or protection against adaptive attackers. I therefore continue to recommend rejection as a completed TSE article, while recognizing a substantially clearer and more defensible scoped artifact.

## Major concerns

1. **Realistic guard-targeting security remains untested.**
   **Location:** Section II/Table I, Theorem 0, Section IV-A, Section V-C family table; `src/tint/layers/__init__.py`, `experiments/dataset.py`.
   **Why:** The vulnerable judge is programmed to accept an exact phrase, while the structured judge applies deterministic rules to a representation that cannot contain that phrase. The revision now correctly says that mixture prevalences and scripted mechanisms imply the improvement; this improves interpretation but does not make it independent security evidence. The canonical secret-egress attack is also prevented by the ordinary mandatory sink alone.
   **Resolution:** Preserve these as executable counterexamples, then evaluate independently authored attacks against learned judges under matched tools, privileges, mediation, and budgets. Include semantic attacks that require judgment and authorized requests whose useful evidence quarantine may remove. No wording-only revision can establish that security benefit.

2. **Practical SE value and sufficient novelty remain unestablished.**
   **Location:** Introduction/RQ III, Tables III–V and Figure 3, Discussion/Conclusion.
   **Why:** The primary method denies every benign fixture; the exploratory calibrated method makes the same decisions as its uncalibrated control. A lexical scorer plus deterministic score cutoff is not evidence about complementary heterogeneous learned guards. There are no completed software changes, patch-correctness measurements, developer outcomes, official defense comparisons, or inference-load costs. The mathematical ingredients and core safety principles are acknowledged prior techniques, so the integration needs a distinctive demonstrated engineering advantage. The new analytical table strengthens the conclusion that repeated seeds estimate one small law rather than diverse task performance.
   **Resolution:** Add real proposal-generating agents and useful development tasks, compare against a hard sink plus one semantic classifier and a relevant maintained defense, and measure task success at matched safety/utility points. Otherwise reposition the contribution around a narrower negative-feasibility or assurance-method result with a corresponding publication scope.

3. **The strongest deterministic premises stop before real agent provenance and execution.**
   **Location:** Definition 1, Section III-D/obligation table; `src/tint/model/__init__.py`, `src/tint/agents/__init__.py`.
   **Why:** The host must supply complete dependency sets, while PATCH writes a constant and mock HTTP records identifiers. There is no exercised model-derived output flow or real adapter establishing that all transmitted content and agent-controlled fields have the necessary labels. The revision now makes this external premise explicit, resolving potential overstatement, but not the engineering gap. This is not an observed bypass of the deliberately closed interpreter.
   **Resolution:** Specify dependencies for each supported field/output and exercise multi-step read/derive/write/send traces through a meaningful adapter. Test omitted references, derived outputs, and secret-bearing targets/arguments. Provide a bounded adapter assurance or refinement argument before extending the claim to host files, shells, or external effects.

4. **The certification evidence does not supply an operational security case for the described attacker.**
   **Location:** Threat model, Section III-B, Section IV-A, Section V-C shift/search discussion.
   **Why:** The attacker may choose subsequent inputs, whereas certification controls fixed-policy joint loss under an iid mixture and a permissive 20% risk budget. The accepted implicit family and 100% encoded-family acceptance show why an attacker need not sample that mixture. Conditional-risk and family reporting now expose this correctly. However, a trusted context string still supplies no procedure for identifying when a certificate should cease authorizing useful actions.
   **Resolution:** Evaluate independently authored held-out families and define context assignment, expiration/recalibration, and treatment of uncertifiable/adaptive traffic, including utility consequences. If these remain future work, keep the contribution explicitly about static workload certification and do not offer the search as robustness evidence.
